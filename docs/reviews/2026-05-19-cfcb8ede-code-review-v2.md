### Outcome

**Verdict:** Not approved

**Reasoning:** The package/resource extraction is broadly solid and the workspace check passes from a clean state, but important verification gaps remain: the Pi discovery probes bypass the package manifest/CLI path they are meant to validate, and the core Node test suite is not hermetic because helper-runner tests generate `__pycache__` that later manifest tests reject.

### Strengths

- The workspace/package split matches the planned core-plus-aggregate architecture, with the aggregate forwarding resources through `node_modules/pi-flow-core/` rather than duplicating source.
- The helper runner has a small, readable implementation with structured errors for missing/unknown resources and no fallback path guessing.
- The migrated Python helper tests are extensive, and `pnpm -r run check` passed after cleaning generated bytecode caches.
- Guardrail-string tests cover several high-risk workflow prompt contracts.

### Issues

#### Critical (Must Fix)

_None._

#### Important (Should Fix)

1. **`test:node` is not repeatable and can fail after its own helper-runner test creates Python bytecode caches.** `packages/pi-flow-core/bin/__tests__/helper-runner.test.mjs:37` runs the Python `execute-plan/extract-plan-tasks` helper, which imports shared modules and creates `skills/_shared/scripts/__pycache__`. `packages/pi-flow-core/__tests__/package-manifest.test.mjs:181` / `:211-212` then asserts there are no `__pycache__` directories under `skills/`, while `packages/pi-flow-core/package.json:12` runs all Node test files together via `node --test`. I reproduced this by running `pnpm --filter pi-flow-core run test:node` twice: the first run left `packages/pi-flow-core/skills/_shared/scripts/__pycache__`, and the second run failed in `excluded artifacts are absent`. Because Node may also schedule test files differently, this is a real flake in the required test command. Make the test suite hermetic by disabling bytecode generation for spawned Python helpers (`PYTHONDONTWRITEBYTECODE=1`), cleaning before/after `test:node`, or changing the artifact-absence assertion to inspect tracked/package contents rather than runtime-generated ignored files.

2. **The Pi discovery probes do not exercise Pi package/manifest discovery as required.** `packages/pi-flow-core/__tests__/package-manifest.test.mjs:289-312` and `packages/pi-flow/__tests__/aggregate-forwarding.test.mjs:155-182` only check `which pi`, import Pi internals, and call `loadSkillsFromDir` on hard-coded skills directories. That bypasses the actual `pi.skills` manifest values and aggregate forwarding path that the plan asked the probes to validate via a conditional `spawnSync('pi', ...)`/`pi -e <package>`-style check. Related manifest tests at `packages/pi-flow-core/__tests__/package-manifest.test.mjs:243-253` and `packages/pi-flow/__tests__/aggregate-forwarding.test.mjs:61-75` read `globPattern` but then ignore it and manually scan fixed directories, so they would still pass if the manifest glob regressed. Update these tests to expand the actual manifest glob and, when Pi is available, run the documented CLI/package discovery path or another probe that starts from the package manifest rather than from a hard-coded directory.

#### Minor (Nice to Have)

- `pnpm-workspace.yaml:3` adds `autoInstallPeers: false` even though the plan specified the workspace file should contain exactly the two-line `packages/*` block. If this is intentional to avoid installing the deferred `pi-interactive-subagent` peer, document the deviation; otherwise remove it for stricter plan fidelity.

### Recommendations

- After fixing the test/probe issues, run `pnpm install`, `pnpm -r run check`, and `pnpm --filter pi-flow-core run test:node` twice in a row to prove the suite is clean-state independent.
- Prefer tests that expand and assert the actual `package.json` `pi.skills` glob values instead of duplicating the expected path in test code.
