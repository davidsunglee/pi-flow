# Add frontier model tier, rename cheap to efficient, and standardize tier field naming to model_tier

Source: IDEA-4ec46eb6

## Goal

Introduce a new abstract logical model tier named `frontier` above `capable`, rename the existing `cheap` tier to `efficient`, and standardize every consumer-side tier field/flag onto a single `model_tier` naming convention across pi-flow. The `frontier` tier lets workflows express "use a frontier-class model" without hardcoding model names in skill logic; `spec-designer` and `planner` are routed through it so future model churn stays isolated to flow configuration. The rename and naming standardization are clean hard cutovers — pi-flow has no external users or long-lived third-party configs, so no aliases, fallbacks, or compatibility shims are kept.

## Context

pi-flow resolves all workflow dispatch through `~/.pi/agent/flow.json` (mirrored by `.pi/flow.json` and `packages/pi-flow-core/flow.example.json`). The config defines two tier sections — `modelTiers` (provider-preferred) and `crossProviderModelTiers` — each currently holding `capable`, `standard`, and `cheap` model strings. There is no abstract tier above `capable`. `anthropic/claude-fable-5` is now the active frontier-class model in the Pi environment.

Dispatch resolution is centralized in `packages/pi-flow-core/skills/_shared/scripts/resolve-model-dispatch.py`, which takes a `--tier` argument holding a **section-qualified path** (e.g. `modelTiers.capable`, `crossProviderModelTiers.cheap`) — the section prefix selects provider-preferred vs cross-provider routing — and prints the `{model, cli, provider, tier, executionPolicy}` envelope. The contract and canonical failure templates live in `packages/pi-flow-core/skills/_shared/dispatch-contract.md`; the user-facing config reference is `packages/pi-flow-core/docs/flow-config-setup.md`.

The same abstract "which tier" concept is currently named four different ways across consumers:
- `planner.md` emits a per-coder-task `**Model recommendation:**` markdown label; `skills/execute-plan/scripts/extract-plan-tasks.py` parses it into a `model_recommendation` JSON key with `VALID_MODELS = {"cheap", "standard", "capable"}`.
- `skills/fastlane/SKILL.md` carries a `coder_tier` run-state alias.
- `skills/scout/SKILL.md` and `resolve-model-dispatch.py` use a `--tier` CLI flag.

Current `modelTiers.capable` dispatch sites for the two agents being re-routed:
- `skills/define-spec/SKILL.md` (Step 3a + task-entry model line + failure-handling note) dispatches `spec-designer`.
- `skills/generate-plan/SKILL.md` (Step 2) dispatches the initial `planner`.

Tier references and `cheap` literals are spread across config, the dispatch contract, skill docs, the planner rubric, the execute-plan model-recommendation table and `(m) Better model` escalation ladder, scout/fastlane menus, the pi-flow-core README, and a large body of tests and execution-plan fixtures (`extract-plan-tasks`, `plan-fence-hardening`, `resolve-model-dispatch`, and `skills/execute-plan/scripts/tests/fixtures/plan-*.md`).

## Requirements

**Config — add `frontier`, rename `cheap`→`efficient`** (in `.pi/flow.json` and `packages/pi-flow-core/flow.example.json`):
- Add `modelTiers.frontier` = `anthropic/claude-fable-5`.
- Add `crossProviderModelTiers.frontier` = `openai-codex/gpt-5.5` (until a newer cross-provider frontier model is available).
- Rename `modelTiers.cheap` → `modelTiers.efficient` (keeping the existing model value).
- Rename `crossProviderModelTiers.cheap` → `crossProviderModelTiers.efficient` (keeping the existing model value).

**Route spec-designer and planner through frontier:**
- `define-spec` resolves `spec-designer` through `modelTiers.frontier` instead of `modelTiers.capable` (Step 3a invocation, the task-entry `model` line, and the failure-handling note that names the tier).
- `generate-plan` resolves the **initial** `planner` dispatch through `modelTiers.frontier` instead of `modelTiers.capable`.

**Standardize consumer-side field/flag naming to `model_tier`:**
- Plan markdown label `**Model recommendation:**` → `**Model tier:**` (planner output + execute-plan/extract-plan-tasks parsing + all fixtures).
- `extract-plan-tasks.py` JSON key `model_recommendation` → `model_tier` (and docstring references).
- `fastlane` run-state alias `coder_tier` → `model_tier`.
- CLI flag `--tier` → `--model-tier` on `resolve-model-dispatch.py`, `scout`, and **every** dispatch-site invocation of the helper (the flag still carries the section-qualified path; the path form itself is unchanged).

**Make `frontier` selectable everywhere `efficient`/`standard`/`capable` are** (one consistent four-tier vocabulary):
- `planner.md` model-tier rubric: rename `cheap`→`efficient`, add a `frontier` entry with selection guidance.
- `extract-plan-tasks.py` `VALID_MODELS` → `{"efficient", "standard", "capable", "frontier"}`.
- `execute-plan` model-tier table: rename the `cheap`→`efficient` row (mapping to `modelTiers.efficient`), add a `frontier` row (mapping to `modelTiers.frontier`); extend the `(m) Better model` escalation ladder to `efficient → standard → capable → frontier`.
- `scout --model-tier` recognized values: `efficient`, `standard`, `capable`, `frontier` (default remains `standard`).
- `fastlane` `model_tier` menu values: `efficient`, `standard`, `capable`, `frontier`.

**Propagate the rename across docs, tests, and fixtures:**
- `dispatch-contract.md`: config-shape examples, tier-path-resolution primitive list, the Template (2) worked example, and any `--tier`→`--model-tier` invocation references all updated to `efficient` and the four-tier set.
- `packages/pi-flow-core/docs/flow-config-setup.md`: config-shape examples, tier-name list, and the mapping table updated to `efficient` + `frontier`.
- `packages/pi-flow-core/README.md`: tier documentation describes the canonical tiers as `frontier`, `capable`, `standard`, `efficient`.
- `test-runner-dispatch.md`: `crossProviderModelTiers.cheap` → `crossProviderModelTiers.efficient`.
- Test fixtures `flow-complete.json`, `flow-no-dispatch.json`, `flow-missing-provider.json`, `flow-coordinator.json`: `cheap` → `efficient`.
- Tests updated/added: `test_resolve_model_dispatch.py` (frontier resolution, cross-provider frontier resolution, `efficient` cutover, `--model-tier` flag), `test_extract_plan_tasks.py` and `test_plan_fence_hardening.py` (`model_tier` key, `**Model tier:**` label, `efficient`/`frontier` values), and the `skills/execute-plan/scripts/tests/fixtures/plan-*.md` fixtures (`**Model recommendation:** cheap` → `**Model tier:** efficient`).

## Constraints

- **Clean hard cutover, no aliases.** No `cheap` tier spelling, no `model_recommendation`/`coder_tier`/`--tier` field-or-flag spelling, and no deprecated-alias/fallback/compatibility-shim path may remain in pi-flow-owned code for model-tier resolution or workflow settings.
- **Config section keys are not renamed.** The JSON objects `modelTiers` / `crossProviderModelTiers` and the section-qualified path form (`modelTiers.frontier`, `crossProviderModelTiers.frontier`) stay as-is — the section prefix encodes provider-preferred vs cross-provider routing, which a bare `model_tier` token cannot carry. Standardization applies only to the consumer-side fields/flags that pass a bare tier alias.
- **Abstract tier names stay in skill and workflow logic.** Concrete model names (`anthropic/claude-fable-5`, `openai-codex/gpt-5.5`, etc.) belong in configuration, documentation examples, and resolution tests — never inlined at skill dispatch sites.
- **Frontier provider mappings are fixed:** provider-preferred `modelTiers.frontier` = `anthropic/claude-fable-5`; cross-provider `crossProviderModelTiers.frontier` = `openai-codex/gpt-5.5`.
- Cross-provider frontier resolution depends on an `openai-codex` entry already present in `subagentDispatch`; no new dispatch-map plumbing is introduced by this change.

## Acceptance Criteria

- `pi-flow helper _shared/resolve-model-dispatch --model-tier modelTiers.frontier --agent spec-designer` resolves successfully when `modelTiers.frontier` = `anthropic/claude-fable-5`.
- `pi-flow helper _shared/resolve-model-dispatch --model-tier modelTiers.frontier --agent planner` resolves successfully under the same config.
- `define-spec` resolves `spec-designer` through `modelTiers.frontier`.
- `generate-plan` resolves the initial `planner` dispatch through `modelTiers.frontier`.
- `crossProviderModelTiers.frontier` exists and resolves through the existing dispatch helper when set to `openai-codex/gpt-5.5` and an `openai-codex` `subagentDispatch` mapping is present.
- All pi-flow-owned tier references use `efficient` instead of `cheap`; no `cheap` spelling, alias, or fallback remains for model-tier resolution or workflow settings.
- Behaviors that previously selected the low-cost/fast tier now select `efficient` via the renamed path.
- Every consumer-side tier field/flag uses the `model_tier` convention: plan label `**Model tier:**`, `extract-plan-tasks` JSON key `model_tier`, fastlane run-state `model_tier`, and the `--model-tier` CLI flag; no `model_recommendation`, `coder_tier`, or `--tier` spelling remains.
- `frontier` is a selectable value in the planner rubric, `extract-plan-tasks` `VALID_MODELS`, the execute-plan model-tier table and `(m) Better model` escalation ladder, `scout --model-tier`, and the fastlane `model_tier` menu.
- Tests cover: frontier tier resolution, `spec-designer`/`planner` frontier dispatch selection, cross-provider frontier resolution, the `cheap`→`efficient` cutover, the `model_tier`/`--model-tier` rename, and parser/fixture updates for execution-plan model-tier recommendations.
- Documentation (dispatch-contract, flow-config-setup, pi-flow-core README) and user-facing menus describe the canonical tiers as `frontier`, `capable`, `standard`, and `efficient`.
- The existing pi-flow test suite passes after the change.

## Non-Goals

- Renaming the JSON config section objects `modelTiers` / `crossProviderModelTiers`, or collapsing the section-qualified path form into a bare token.
- Re-routing any dispatch other than `spec-designer` (via `define-spec`) and the **initial** `planner` (via `generate-plan`) to `frontier` — notably, `refine-plan`'s `planner` edit-pass, `plan-reviewer`/`code-reviewer`, the coordinator chain, and other leaf workers keep their current tiers.
- Changing `coordinatorSubagentDispatch` or coordinator dispatch behavior.
- Adding any backward-compatibility path, deprecation alias, or migration shim for the old `cheap` tier name or the old `model_recommendation`/`coder_tier`/`--tier` field/flag names.
- Selecting a cross-provider frontier model other than `openai-codex/gpt-5.5`, or adding new provider entries to `subagentDispatch`.
