# Rebrand workflow artifacts from TODO-<id> to IDEA-<id>

Source: TODO-d9644bc0
Scout brief: docs/briefs/TODO-d9644bc0-brief.md

## Goal

Replace the legacy `TODO-<id>` / `docs/todos/` terminology and identifier shape throughout pi-flow-core with `IDEA-<id>` / `docs/ideas/`, drop every code path that recognized or emitted `TODO-`, and remove the runtime dependency on the external `todo` tool by routing all idea-artifact state access through the built-in `idea` tool. The cutover is a single coordinated change with no compatibility window; users migrate their on-disk artifacts via a one-time `mv docs/todos docs/ideas`, which is documented but not executed by this work.

## Context

Today the workflow's durable user-intent artifacts are surfaced under "TODO" terminology that collides with generic LLM checklist/planning tools, even though pi-flow already ships the new `idea` command and tool. Key code reality:

- `packages/pi-flow-core/extensions/idea.ts` registers `/flow:idea` and the `idea` tool, but every user-visible string still emits `TODO-${id}` and `IDEA_TOOL_DESCRIPTION` calls the prefix "legacy compatibility."
- `packages/pi-flow-core/extensions/storage.ts` defines `IdeaArtifact` (bare-hex `id` field — no prefix in storage), `getTodoDir()` (hardcodes `docs/todos`, git-root resolved), `normalizeIdeaId()` (strips `TODO-` only), and `isLegacyTodoId()` (unused inside this package).
- `packages/pi-flow-core/extensions/router.ts` uses `TODO_RE = /^(TODO-)?([0-9a-f]{8})$/` and canonicalizes to `TODO-${m[2]}`; downstream `buildExactPrompt` ships that canonical identifier into skill arguments.
- `packages/pi-flow-core/extensions/workflow.ts` `COMMAND_DESCRIPTIONS` reference `TODO-<id>` in user-visible slash-command help.
- The provenance chain — `Source: TODO-<id>` in spec/plan preambles, the `_RE_SOURCE` regex in `packages/pi-flow-core/skills/_shared/scripts/extract-provenance-preamble.py`, the `source_todo` JSON field it emits, `{SOURCE_TODO}` placeholders in `generate-plan/SKILL.md` and `refine-plan/SKILL.md`, and the `**Source:** TODO-<id>` plan header in `packages/pi-flow-core/agents/planner.md` — is exact-match end-to-end. A change anywhere in the chain must propagate through every link in the same changeset.
- Three skills depend on an external `todo` tool that pi-flow does NOT register itself: `generate-plan/SKILL.md` Step 1a (read todo body), `execute-plan/SKILL.md` Step 16.2 (read + close linked todo), and `fastlane/SKILL.md` Step 10.2 (read + close linked todo). The runtime dependency is silent — if the external tool is absent, those steps fail at execution time.
- `scout/SKILL.md` Step 1 already uses direct filesystem reads to extract the todo body (no tool call), establishing the "read artifact from disk" precedent that this spec moves away from in favor of the built-in `idea` tool.
- `define-spec/SKILL.md` Step 3a slug derivation and Step 4 transcript-backed recovery both pin the literal `TODO-<id>` line/path shapes; `spec-design-procedure.md` Step 1 and `scout/SKILL.md` Step 1 likewise.
- Test surface: `extensions/router.test.ts` (~50 tests pinned on `TODO-abcd1234` fixtures), `extensions/idea.test.ts` (tool output and notify assertions against `/TODO-[0-9a-f]{8}/`), `skills/_shared/scripts/tests/test_extract_provenance_preamble.py` (TODO-only fixtures), `skills/define-spec/scripts/tests/test_todo_input_shape.py` (regex contract test), `skills/refine-plan/scripts/tests/test_prepare_plan_*` (CLI arg fixtures).
- Existing on-disk artifacts in this repo: 5 files under `docs/todos/` (`cfcb8ede.md`, `8c3886f2.md`, `ef562e4d.md`, `e13e219c.md`, `d9644bc0.md`). Bare-hex filenames carry no prefix; the directory name is the only filesystem-side `todo` reference.

## Requirements

Identifier and terminology surface:
- All user-visible and LLM-visible strings emitted by `extensions/idea.ts`, `extensions/workflow.ts`, and any other extension use `IDEA-<8hex>` as the canonical identifier form. No `TODO-` mention remains in `IDEA_TOOL_DESCRIPTION`, `promptSnippet`, `COMMAND_DESCRIPTIONS`, notify messages, tool result text, or error strings.
- `normalizeIdeaId` strips only the `IDEA-` prefix (case-insensitive); inputs prefixed with `TODO-` are no longer normalized and yield `undefined`.
- `router.ts` recognizes `IDEA-<8hex>` (and bare 8-hex, preserving today's shortcut behavior); inputs of the form `TODO-<8hex>` are not recognized as artifact tokens (they fall through to interpreted routing or are rejected under `--exact`).
- `isLegacyTodoId` is removed from `storage.ts` (and any unused export sites updated).
- `getTodoDir` is renamed (e.g., `getIdeaDir`) and resolves to `<git-root>/docs/ideas` (writers and readers both target this path; no fallback to `docs/todos/`).

Provenance chain:
- The `Source:` line shape in spec and plan preambles becomes `Source: IDEA-<8hex>` (with `**Source:** IDEA-<8hex>` accepted as the bold variant, mirroring today's parser).
- `extract-provenance-preamble.py` matches only the `IDEA-<8hex>` form and emits the JSON field name `source_idea` (renamed from `source_todo`). The brief-mode `Git SHA:` behavior is unchanged.
- Every consumer of the JSON output renames its placeholder/argument accordingly: `generate-plan/SKILL.md` Step 1b sets `{SOURCE_IDEA}` to `Source idea: IDEA-<id>`; `generate-plan/SKILL.md` Step 3 fill-instructions and the planner prompt template update the placeholder name; `refine-plan/SKILL.md` input table and Step 3 auto-discover rename the `SOURCE_TODO` field and the `--source-todo` flag (e.g., `--source-idea`); the planner agent emits `**Source:** IDEA-<id>` in the plan header.
- `execute-plan/SKILL.md` Step 16.2 scans for `**Source:** IDEA-<id>` (not `TODO-`); `fastlane/SKILL.md` Step 10.2 likewise.

Brief path:
- Scout writes briefs to `docs/briefs/IDEA-<raw-id>-brief.md` (todo branch); `spec-design-procedure.md` Step 1 and `define-spec/SKILL.md` Step 3a check only that path. Scout's continuation hint (`Run /define-spec IDEA-<id> next?`) uses the new prefix.

Input-detection regexes in skill prose:
- `scout/SKILL.md` Step 1, `define-spec/SKILL.md` Step 3a, and `spec-design-procedure.md` Step 1 input-shape table use `^IDEA-[0-9a-f]{8}$` (case-insensitively, where the existing rule was case-insensitive); the `TODO-` alternative is removed.
- `define-spec/SKILL.md` Step 4 transcript-backed recovery's provenance-line check uses `Source: IDEA-<id>`.

Test-run directory:
- `fastlane/SKILL.md` Step 6 names the per-run directory `docs/test-runs/IDEA-<id>/` when the input was an idea ID (not `TODO-<id>/`).

Skill-to-artifact access — architecture-round outcome (see `## Approach`):
- `generate-plan/SKILL.md` Step 1a calls the built-in `idea` tool (`action: "read"`) to fetch the body for inlining into the planner prompt.
- `execute-plan/SKILL.md` Step 16.2 calls the built-in `idea` tool (`action: "read"` then `action: "update"` with status `done` and the completion line appended to the body).
- `fastlane/SKILL.md` Step 10.2 calls the built-in `idea` tool (same shape as `execute-plan`).
- `scout/SKILL.md` Step 1 migrates from its current direct-file read to the built-in `idea` tool (`action: "read"`) so that all idea-artifact access in skills goes through the same interface. Scout's title-fallback rules (JSON metadata block first, then first `# ` heading outside fences, then explicit failure) are preserved in skill prose but driven from the tool's structured `details` payload rather than inline JSON parsing.
- The external `todo` tool is no longer referenced anywhere in pi-flow-core skill prose, agent docs, or helper scripts. The `_shared` tool-availability table in `execute-plan/SKILL.md` Step 9 drops the `todo tool` row.

Test coverage:
- TypeScript: `extensions/router.test.ts`, `extensions/idea.test.ts`, `extensions/storage.test.ts` updated so all canonical fixtures and assertions use `IDEA-<8hex>` (or bare hex where appropriate); the `does not leak todo command or tool names` assertion in `idea.test.ts` is preserved.
- Python: `skills/_shared/scripts/tests/test_extract_provenance_preamble.py` and its fixture files (`preamble-spec-clean.md`, `preamble-spec-fenced-heading.md`) updated to `IDEA-<id>` cases and the `source_idea` output key; `skills/define-spec/scripts/tests/test_todo_input_shape.py` updated to pin the new `IDEA-<8hex>` regex (file rename optional but encouraged); `skills/refine-plan/scripts/tests/test_prepare_plan_*` updated to the renamed flag/field.
- New coverage: at least one test demonstrates that `generate-plan`/`execute-plan` orchestration runs end-to-end with only the built-in `idea` tool registered (no external `todo` tool).

Documentation:
- A README (or equivalent doc surface in pi-flow-core) explains the terminology change, the rationale ("avoid clash with generic todo/checklist tools"), and the one-time user migration step: `mv docs/todos docs/ideas` per project.

## Constraints

- Single coordinated changeset: every parser, writer, consumer, regex, fixture, and prose reference flips in one PR. Partial updates would break the provenance chain (e.g., a writer emitting `IDEA-` while a reader still requires `TODO-` silently drops the link).
- Hard cutover with zero `TODO-` compatibility: no dual-accept anywhere (router, normalizer, provenance parser, brief loader, skill input regexes). Inputs of the form `TODO-<8hex>` are not recognized as artifact tokens after this change.
- Do not rewrite preamble content of existing on-disk specs, plans, briefs, or reviews. Their stale `Source: TODO-<id>` and `Scout brief: docs/briefs/TODO-<id>-brief.md` lines will not parse under the new regex, and that is acceptable — the user has stated those artifacts are completed and deletable.
- Do not add environment-variable customization of the storage path. `getIdeaDir` resolves the git root only, matching how other pi-flow workflow artifact paths (specs, plans, briefs, reviews) work.
- Do not perform the cross-project filesystem migration from this codebase. The `mv docs/todos docs/ideas` step is a manual one-liner that users (including this repo's maintainer) run against each project's working directory; the work here is purely the source-code rebrand.
- The on-disk JSON metadata `id` field (bare 8-hex) is unchanged. No artifact file format change, no on-disk rewrite tooling. Only the directory name and the prefix used in user-facing strings change.
- The `IdeaArtifact` TypeScript interface and the existing read/write/list/parse functions in `storage.ts` keep their current shape and semantics; only path resolution and the prefix-stripping behavior of `normalizeIdeaId` change.

## Approach

**Chosen approach:** All skill-level access to idea artifacts (read body, read status, update status, append to body) is routed through the built-in `idea` tool's `read` and `update` actions. This applies to `generate-plan`, `execute-plan`, `fastlane`, AND `scout` — the latter being migrated for consistency even though its current direct-file-read pattern works.

**Why this over alternatives:** The `idea` tool is the new abstraction for idea-artifact state, so having skills route through it sends a clean signal that `idea` is THE interface. It tightens skill prose (one structured tool call instead of multi-step file ops + JSON parsing), encapsulates atomic-write semantics inside `storage.ts:writeIdea`, and gives all four skills a single consistent test surface (register `idea` once, no fixture file plumbing). The "couples skills to the tool being registered" concern is moot in practice because pi-flow always registers `idea`, and a runtime-missing tool would fail loudly rather than silently.

**Considered and rejected:**

- **Hybrid (direct filesystem reads, `idea` tool for writes)** — Reads would match scout's current cat+JSON pattern; writes would route through the tool for atomic semantics. Rejected: two interfaces for the same resource creates maintenance ambiguity, and the JSON-parsing prose embedded in `scout/SKILL.md:20` is exactly the kind of brittle detail this rebrand is a good opportunity to delete.
- **Direct filesystem I/O throughout (no tool dependency)** — Skills would describe both reads and writes inline (open, JSON parse, atomic write-then-rename). Rejected: duplicates `storage.ts` logic in skill prose, the atomic-write protocol is fragile to specify in markdown, and pi-flow already always ships the `idea` tool so the "portability" benefit is theoretical.

## Acceptance Criteria

- A repo-wide grep for `TODO-` in `packages/pi-flow-core/` (extensions, skills, agents, helper scripts, fixtures, tests) returns zero matches outside of immutable history surfaces (e.g., committed changelogs, prior commit messages). The spec preamble of this very file is permitted as the sole exception, since it records the input under which this work was specified.
- A repo-wide grep for the external `todo` tool (as a tool name or extension reference) in pi-flow-core skill prose, agent docs, and helper scripts returns zero matches.
- `/flow:scout`, `/flow:spec`, `/flow:plan`, and other workflow slash commands accept `IDEA-<8hex>` as the canonical typed artifact identifier and reject `TODO-<8hex>` as not-an-artifact-token (it falls through to interpreted routing or fails `--exact` validation).
- Newly generated specs, plans, briefs, and reviews emit `IDEA-<id>` in their `Source:` lines, `Scout brief:` paths, plan headers, and continuation prompts.
- `extract-provenance-preamble.py` returns `source_idea` in its JSON output (the key is `source_idea`, not `source_todo`), populated only when a `Source: IDEA-<8hex>` line is present in the preamble.
- Running `generate-plan` against an `IDEA-<id>` input produces a plan whose `**Source:**` line references `IDEA-<id>`, and `execute-plan` against that plan successfully reads and closes the linked artifact via the built-in `idea` tool.
- All existing TypeScript and Python tests pass after their fixtures and assertions have been updated to the `IDEA-`/`source_idea` shape.
- A new test asserts that `generate-plan` and `execute-plan` complete end-to-end with only the built-in `idea` tool registered (no external `todo` tool present).
- The README (or equivalent docs surface) documents the rebrand, the rationale, and the user-facing `mv docs/todos docs/ideas` migration step.

## Non-Goals

- Backward compatibility for `TODO-<id>` input at any layer (router, normalizer, provenance parser, brief loader, skill input regexes). Explicitly out of scope; the documented migration is `mv docs/todos docs/ideas`.
- Read-side fallback in pi-flow code that resolves `docs/todos/` if `docs/ideas/` is empty. Explicitly out of scope.
- Rewriting the preamble lines of existing on-disk specs, plans, briefs, or reviews (whether in this repo or in users' other projects).
- Environment-variable support for storage-path customization (`PI_IDEA_PATH`, `PI_TODO_PATH`, or any other override). Deferred indefinitely; matches how other workflow artifact paths behave today.
- Cross-project execution of the filesystem migration (e.g., a script that walks `~/Code/*` and renames `docs/todos/` → `docs/ideas/`). The migration is documented as a manual one-liner; this work does not ship tooling for it.
- Renaming the on-disk JSON metadata `id` field or any other change to the artifact file format.
- Repurposing or relocating `isLegacyTodoId`. It is deleted outright.
