# Prepare pi-flow packages for npm publication under @aphotic

Source: IDEA-54a0dbec

## Goal

Prepare the pi-flow monorepo to publish its three workspace packages as `@aphotic/pi-flow`, `@aphotic/pi-flow-core`, and `@aphotic/pi-flow-ux` at version `0.5.0` on npm. `@aphotic/pi-flow` remains the documented default aggregate install; the core and UX packages are available as independently installable advanced options. This spec covers publication preparation only — the actual `pnpm publish` is a subsequent manual step.

## Context

pi-flow is a pnpm monorepo (`packages/*`) with three workspace packages:

- **`pi-flow`** (aggregate): depends on `pi-flow-core` and `pi-flow-ux` via `workspace:*`, forwards skills/extensions/themes through `node_modules/pi-flow-core/...` and `node_modules/pi-flow-ux/...` paths in its `pi` manifest, and exposes a thin bin wrapper that delegates to core's runner.
- **`pi-flow-core`**: workflow skills, bundled agent definitions, helper runner binary, and the `extensions/commands.ts` extension. Declares `typebox` as both a regular dependency (runtime import from `extensions/idea.ts`) and a peer dependency.
- **`pi-flow-ux`**: optional UX layer — footer extension, working indicator, Nord theme, and packaged working defaults.

All three currently use unscoped names (`pi-flow`, `pi-flow-core`, `pi-flow-ux`) and are marked `private: true`. The unscoped `pi-flow` name on npm is owned by another project, so publication must use the existing `@aphotic` organization scope (matching the already-published `@aphotic/pi-mux-subagents`).

Key codebase details relevant to this work:

- The aggregate's `pi` manifest references dependency paths like `node_modules/pi-flow-core/skills/*/SKILL.md` — these must become `node_modules/@aphotic/pi-flow-core/...` after renaming.
- The aggregate's bin wrapper (`packages/pi-flow/bin/pi-flow.mjs`) resolves `pi-flow-core/bin/pi-flow.mjs` via `createRequire` — must update to `@aphotic/pi-flow-core/bin/pi-flow.mjs`.
- The core's helper-runner docs (`docs/helper-runner.md`, `docs/model-tier-setup.md`) reference `node_modules/pi-flow-core/...` fallback paths.
- Package READMEs reference unscoped install paths and `node_modules/pi-flow-*/...` paths.
- Comprehensive package-manifest tests (`__tests__/package-manifest.test.mjs` in core and ux) and aggregate-forwarding tests (`__tests__/aggregate-forwarding.test.mjs`) hardcode current unscoped names and `node_modules/pi-flow-core` / `node_modules/pi-flow-ux` paths.
- `pi-flow-core` has `"files": ["bin", "skills", "agents", "docs", "extensions", "model-tiers.example.json"]` — the `skills` entry includes nested `tests/` and `fixtures/` directories (e.g., `skills/_shared/scripts/tests/` with ~30 fixture files, `skills/execute-plan/scripts/tests/` with ~25 fixtures) that would ship in the tarball unintentionally.
- No LICENSE file, `.npmignore` files, or `publishConfig` fields exist anywhere in the repo.
- Peer dependencies for `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, and `typebox` currently use `*` (any version) ranges.
- The workspace root (`pi-flow-workspace`) is already `private: true` and must stay that way.

## Requirements

- Rename package `name` fields to `@aphotic/pi-flow`, `@aphotic/pi-flow-core`, and `@aphotic/pi-flow-ux`.
- Set `version` to `0.5.0` in all three publishable packages and the workspace root.
- Remove `private: true` from the three publishable packages.
- Update aggregate `dependencies` keys from unscoped to scoped names (e.g., `"@aphotic/pi-flow-core": "workspace:*"`).
- Update all `pi` manifest paths in the aggregate's `package.json` to use `node_modules/@aphotic/pi-flow-core/...` and `node_modules/@aphotic/pi-flow-ux/...`.
- Update the aggregate bin wrapper's `require.resolve` target from `pi-flow-core/bin/pi-flow.mjs` to `@aphotic/pi-flow-core/bin/pi-flow.mjs`.
- Add npm metadata to each publishable package: `license` (MIT), `repository` (with `directory` field), `bugs`, `homepage`, `author`, `engines` (`node >=20`), and `publishConfig` (`"access": "public"`).
- Create MIT LICENSE file(s) so each published tarball includes the license text.
- Replace wildcard `*` peer dependency ranges with `^major.0.0` caret ranges for `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, and `typebox`, based on the currently installed/tested major versions in the lockfile.
- Preserve `typebox` as both a regular dependency and peer dependency in `@aphotic/pi-flow-core`.
- Add `files` negation patterns to `pi-flow-core`'s `files` array to exclude nested `tests/` directories and test fixtures from the tarball.
- Update existing package-manifest tests to assert scoped package names.
- Update aggregate-forwarding tests to reference `node_modules/@aphotic/pi-flow-core` and `node_modules/@aphotic/pi-flow-ux` paths.
- Add packlist regression tests that verify `pnpm pack --dry-run` output for each package includes only intentional runtime/documentation content and excludes tests, fixtures, and `.gitkeep` files.
- Update all documentation (READMEs, `docs/helper-runner.md`, `docs/model-tier-setup.md`) to use scoped `@aphotic/...` package names and paths.
- Add release documentation covering `pnpm pack --dry-run`, `pnpm publish --dry-run`, and `pnpm publish` workflows.

## Constraints

- Must use `pnpm publish` / `pnpm pack` so workspace `workspace:*` references are rewritten to concrete semver versions in the published tarball.
- Workspace root must remain `private: true`.
- No `.npmignore` files — tarball trimming uses only the `files` allowlist with negation patterns.
- No Changesets or automated versioning integration — deferred until release management becomes painful.
- No install-time side-effect scripts (`preinstall`, `install`, `postinstall`, `setup`) in any publishable package.
- The `pi-flow` bin command name is unchanged in both the aggregate and core packages.

## Acceptance Criteria

- `@aphotic/pi-flow`, `@aphotic/pi-flow-core`, and `@aphotic/pi-flow-ux` appear as package names at version `0.5.0`.
- The workspace root remains `private: true`; the three publishable packages do not have `private: true`.
- `pnpm check` passes after all renaming, metadata, dependency, packlist, and documentation changes.
- `pnpm pack --dry-run` for each package produces a tarball containing only intentional files — no `tests/`, fixture directories, or `.gitkeep` files.
- The aggregate package's packed manifest rewrites `workspace:*` dependencies to publishable `@aphotic/pi-flow-core` and `@aphotic/pi-flow-ux` semver dependencies.
- All internal references (aggregate `pi` manifest paths, bin wrapper `require.resolve`, test assertions, documentation paths) use scoped `@aphotic/...` names.
- Packlist regression tests exist and pass for all three packages.
- Each published tarball includes an MIT LICENSE file.
- Peer dependency versions use `^major.0.0` caret ranges — no `*` wildcards remain.
- Release documentation exists with `pnpm pack --dry-run`, `pnpm publish --dry-run`, and `pnpm publish` steps.

## Non-Goals

- Changesets or automated versioning/release management.
- npm 2FA/OTP guidance or organization access documentation.
- Actually publishing to npm — this spec covers preparation only.
- Changing the `pi-flow` bin command name.
- Creating `.npmignore` files.
