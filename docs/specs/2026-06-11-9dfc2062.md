# Treat a passing test run as an authoritative pass (no false gate-blocks)

Source: IDEA-9dfc2062

## Goal

When a Codex-backed `test-runner` subagent runs a suite that passes (`EXIT_CODE: 0`) but non-deterministically misclassifies the run — pasting passing output into a status field and declaring a failure — the integration gate currently blocks on a suite that actually passed. This work makes the deterministic reconcile layer treat `EXIT_CODE: 0` as an authoritative pass, so a passing run can never be classified as failing or non-reconcilable. This eliminates the false gate-block at its deterministic chokepoint, with no reliance on the LLM classifying correctly.

## Context

`execute-plan` gates each wave on integration tests via a fixed deterministic pipeline:

- The `test-runner` subagent (`packages/pi-flow-core/agents/test-runner.md`) runs the command and **authors a structured artifact itself** (LLM-written), recording stable failures under `FAILING_IDENTIFIERS:` and non-reconcilable evidence (crashes/build errors) under `NON_RECONCILABLE_FAILURES:`. It resolves to Codex (`crossProviderModelTiers.efficient` → `openai-codex/gpt-5.4-mini`).
- `packages/pi-flow-core/skills/_shared/scripts/parse-test-runner-artifact.py` validates/parses the artifact (header order, count-vs-entries reconciliation, raw-output marker, integer parsing) and emits JSON. It reads `EXIT_CODE` but enforces **no** relationship between the exit code and the buckets.
- `packages/pi-flow-core/skills/_shared/scripts/reconcile-test-run.py` calls the parser, then classifies (capture mode for the baseline; reconcile mode for post-wave / final gate). It reads `exit_code` (line 109) but classifies **purely on bucket contents** — a non-empty non-reconcilable bucket ⇒ `fail`, regardless of exit code.
- The `test-runner` agent contract already states the rule: **"When `EXIT_CODE == 0`, both counts MUST be 0."** Nothing enforces it — it is an LLM instruction the model intermittently violates.

**Confirmed concrete failure (pi-flow, 2026-06-09 execute-plan run, pi coordinator session `019eaeb0`):** the suite passed — `EXIT_CODE: 0`, `FAILING_IDENTIFIERS_COUNT: 0`, 254/254 node tests pass, every Python suite `OK` — but the Codex `test-runner` set `NON_RECONCILABLE_COUNT: 1` and copied the entire passing stdout into `NON_RECONCILABLE_FAILURES`. The parser accepted the (structurally valid) artifact; reconcile classified the wave `fail` and blocked the gate. A plain re-dispatch with no code change then produced a clean artifact. The decisive evidence: the *same* passing suite, with the same benign `ResourceWarning` noise from an out-of-scope Python test, recorded `NON_RECONCILABLE_COUNT: 0` at baseline and wave-1 but `1` at wave-2 — i.e. Codex non-deterministically over-interpreted cosmetic warning noise in passing output as a non-reconcilable failure.

## Requirements

- When a structurally valid artifact reports `EXIT_CODE: 0`, the deterministic layer MUST treat the run as an authoritative pass: both `FAILING_IDENTIFIERS` and `NON_RECONCILABLE_FAILURES` are treated as empty regardless of what the artifact declares.
- The override MUST apply uniformly wherever a passing artifact is interpreted — both `reconcile-test-run.py` capture mode (baseline) and reconcile mode (post-wave / final gate) — so a passing baseline records no `baseline_failures` and a passing wave classifies `clean` / `pass`.
- A non-zero `EXIT_CODE` MUST retain today's behavior exactly: buckets are honored; real stable failures and non-reconcilable evidence flow through unchanged.
- The override MUST NOT be silent: when it discards contradictory buckets, the deterministic layer exposes that fact (e.g. a flag plus the discarded counts) and the caller surfaces a one-line warning to the user, analogous to the existing `used_fallback` warning.
- A regression test built from the 2026-06-09 case MUST exist: an artifact with `EXIT_CODE: 0`, empty `FAILING_IDENTIFIERS`, and `NON_RECONCILABLE_COUNT: 1` whose single entry is passing stdout, fed through parse → reconcile, classifies `pass` / clean and does not block the gate.

## Constraints

- Surgical change to the existing deterministic Python helpers (`parse-test-runner-artifact.py` and/or `reconcile-test-run.py`). No new helper subsystem; no change to the orchestrator's execution boundary.
- The orchestrator MUST NOT run the configured test command itself or synthesize an artifact — unchanged. Test execution stays in the `test-runner` subagent.
- All existing structural validations in `parse-test-runner-artifact.py` (header presence/order, count-vs-entries reconciliation, raw-output marker, integer parsing) MUST remain intact. The exit-0 override is applied to artifacts that are *already* structurally valid; it adds a semantic invariant on top and relaxes no existing check. (The 2026-06-09 artifact was structurally valid — its declared counts matched its entries — and merely violated the exit-0 invariant.)
- The fix must be fully deterministic — no reliance on the LLM classifying correctly, and no change to the `test-runner` agent/prompt instructions.

## Approach

**Chosen approach:** Treat `EXIT_CODE: 0` as an authoritative pass in the deterministic layer. When the exit code is 0, the buckets are overridden to empty (the agent contract already declares exit-0 ⇒ empty buckets), so reconcile classifies the run `clean` / `pass` and surfaces a one-line warning that contradictory buckets were ignored. The natural single chokepoint is the shared parser that `reconcile-test-run.py` already calls, so every consumer (baseline capture, wave reconcile, final gate, and the dispatch-validation path) inherits the invariant uniformly; exact placement and the override-vs-flag data shape are left to the planner.

**Why this over alternatives:** It directly guarantees the stated goal — a passing suite can never false-block the gate — on the first attempt, deterministically, with zero dependence on Codex getting classification right, while remaining a small change to existing helpers.

**Considered and rejected:**

- **Reject-and-retry** (parser flags exit-0 + nonzero buckets as a new malformed sub-reason; the existing malformed-artifact path re-dispatches `test-runner`) — conservative and keeps the parser a pure validator, but costs a retry and can re-loop if Codex misclassifies again, so it does not *guarantee* the passing run passes; it only trusts the next dispatch.
- **Deterministic write-time wrapper** (a new helper the `test-runner` calls to run the command and write the artifact, hard-coding empty buckets when exit code is 0) — prevents the bad artifact at the source, but adds a new helper and rewires the agent/prompt execution path — far larger than a one-line semantic invariant warrants, and counter to the surgical scope.

## Acceptance Criteria

- An artifact matching the 2026-06-09 case (`EXIT_CODE: 0`, `FAILING_IDENTIFIERS_COUNT: 0`, `NON_RECONCILABLE_COUNT: 1` whose single entry is passing stdout), fed through parse → reconcile in reconcile mode, yields `classification: pass` with empty `current_non_reconcilable` and `current_non_baseline_stable`, and the gate does not block.
- The same exit-0 artifact in capture mode yields a `clean` classification with empty `baseline_failures`.
- An exit-0 artifact that bogusly lists entries under `FAILING_IDENTIFIERS` yields empty `failing_identifiers` and a passing classification.
- A genuinely failing artifact (`EXIT_CODE` ≠ 0) carrying non-reconcilable evidence still classifies `fail` — no regression to the real-failure path.
- When the override fires, an observable signal is present (a helper-output flag and/or a one-line caller warning); when the exit code is non-zero or the buckets are already empty, no such signal appears.
- All pre-existing `parse-test-runner-artifact.py` and `reconcile-test-run.py` tests continue to pass.

## Non-Goals

- The shortened / `header_missing` artifact failure mode — considered fixed via Codex subagent-identity delivery; not addressed here.
- Generic artifact-validation hardening beyond the single exit-0 invariant.
- Any per-agent or non-Codex dispatch-policy routing for `test-runner`.
- Runtime/version-alignment verification or a live Codex smoke run as binding, automated acceptance (a manual smoke remains optional and is not a deliverable of this spec).
- A deterministic write-time artifact wrapper, or any change to the `test-runner` agent/prompt LLM instructions (the contract already states exit-0 ⇒ empty buckets; no instruction change is required).
- Changing reconcile semantics for non-zero-exit runs.

## Open Questions

- Beyond the user-facing one-line warning, should the helper retain the discarded bucket contents in its JSON output (an audit field) so repeated Codex misclassification stays diagnosable, or is a boolean flag plus the discarded counts sufficient?
