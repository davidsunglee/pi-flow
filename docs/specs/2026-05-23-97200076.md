# Decouple fastlane from execute-plan internals

Source: IDEA-97200076

## Goal

Eliminate `fastlane`'s reliance on `execute-plan` internal files, helpers, and mirrored step-number references by relocating the reusable primitives into `skills/_shared/` and replacing the mirrored-language references with small contract-style docs that both skills can consume. After the change, `fastlane/SKILL.md` no longer reads from `skills/execute-plan/`, no longer invokes `pi-flow helper execute-plan/parse-coder-report`, and no longer says "mirror execute-plan Step <N>"; `execute-plan/SKILL.md` reads from the same shared primitives. The shared assets stay small and contract-focused, matching the existing `_shared/*.md` style.

## Context

Current coupling that this refactor targets:

- `packages/pi-flow-core/skills/fastlane/SKILL.md` references `skills/execute-plan/` at four sites:
  - Step 4 `{TDD_BLOCK}` placeholder is sourced from `skills/execute-plan/tdd-block.md` (read from disk and fed through `pi-flow helper _shared/fill-template`).
  - Step 5 parses the coder's `finalMessage` via `pi-flow helper execute-plan/parse-coder-report`.
  - Step 5 status routing language says it is "mirroring `skills/execute-plan/SKILL.md` Step 9".
  - Step 10 idea closure says it is "Mirror `skills/execute-plan/SKILL.md` Step 16.2".
- `packages/pi-flow-core/skills/execute-plan/SKILL.md` Step 8 dispatches coders through `pi-flow helper execute-plan/assemble-coder-prompt`, which reads `tdd-block.md` from its sibling directory via the `--tdd-block-template` default; Step 9 owns the canonical status-routing text; Step 16.2 owns the canonical linked-idea-closure procedure.
- `packages/pi-flow-core/skills/execute-plan/scripts/parse-coder-report.py` is the only parser of coder reports; its fixtures (`coder-report-done.md`, `coder-report-done-with-concerns.md`, `coder-report-blocked.md`, `coder-report-needs-context.md`, `coder-report-no-status.md`, `coder-report-bad-status.md`, `coder-report-concerns-missing.md`) and `test_parse_coder_report.py` live under `skills/execute-plan/scripts/tests/`.
- `packages/pi-flow-core/bin/pi-flow.mjs` resolves `pi-flow helper <location>/<name>` literally to `skills/<location>/scripts/<name>.py`, so changing the resource ID requires only moving the script and updating the two call sites.
- `packages/pi-flow-core/skills/_shared/` already hosts contract-style docs (`coordinator-dispatch.md`, `test-runner-dispatch.md`, `model-tier-resolution.md`, `orchestrator-verification-boundary.md`) that the new shared assets should match in tone and size.
- `packages/pi-flow-core/scripts/run-helper-tests.ts` already iterates both `skills/_shared/scripts/tests` and `skills/execute-plan/scripts/tests`, so a parser-test relocation into `_shared/scripts/tests/` is picked up automatically.

The two source-lookup rules for the linked-idea-closure step differ by design and stay caller-local:
- `execute-plan` scans the plan body for `**Source:** IDEA-<id>` and appends `Completed via plan: docs/plans/<plan-filename>.md`.
- `fastlane` uses the original input idea ID directly when the input was an idea, otherwise extracts `Source: IDEA-<id>` from the spec preamble; it appends `Completed via fastlane: <commit SHA>, spec: <spec path>` (or `spec: (input was idea)`).

## Requirements

Asset moves:

- Move `packages/pi-flow-core/skills/execute-plan/tdd-block.md` to `packages/pi-flow-core/skills/_shared/coder-tdd-block.md`. File content stays workflow-neutral (it already is).
- Move `packages/pi-flow-core/skills/execute-plan/scripts/parse-coder-report.py` to `packages/pi-flow-core/skills/_shared/scripts/parse-coder-report.py`. Parser behavior, CLI surface, exit codes, stderr/stdout shape, and protocol-error/warning labels are preserved byte-for-byte; only the file location and helper resource ID change. The `from fence_aware import ...` import path inside the script must be updated to reflect the new location (the helper now lives one directory closer to `_shared/scripts/`, so the `sys.path.insert(...)` line that walks up to `_shared/scripts` adjusts accordingly).
- Move the parser's coder-report fixtures (`coder-report-done.md`, `coder-report-done-with-concerns.md`, `coder-report-blocked.md`, `coder-report-needs-context.md`, `coder-report-no-status.md`, `coder-report-bad-status.md`, `coder-report-concerns-missing.md`) from `skills/execute-plan/scripts/tests/fixtures/` to `skills/_shared/scripts/tests/fixtures/`. Other fixtures under `execute-plan/scripts/tests/fixtures/` (for `extract-plan-tasks`, verifier reports, etc.) stay where they are.
- Move `test_parse_coder_report.py` from `skills/execute-plan/scripts/tests/` to `skills/_shared/scripts/tests/`. The relative `SCRIPT` constant (`os.path.join(os.path.dirname(__file__), "..", "parse-coder-report.py")`) and `FIXTURES` constant (`os.path.join(os.path.dirname(__file__), "fixtures")`) continue to resolve correctly from the new location and do not need to change.
- No compatibility shim under `skills/execute-plan/scripts/parse-coder-report.py`. Both call sites flip to `pi-flow helper _shared/parse-coder-report` in the same change.

New shared docs (small, contract-focused, modeled on `_shared/coordinator-dispatch.md`):

- Add `packages/pi-flow-core/skills/_shared/coder-report-contract.md` describing:
  - The four valid statuses (`DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`) and their semantics from an orchestrator-routing perspective.
  - The `pi-flow helper _shared/parse-coder-report --report <path-or-dash>` invocation and the fields callers consume from its stdout JSON (`status`, `files_changed`, `concerns_block`, `blocker_text`, `needs_text`, `tests_block`, `completed_block`, `self_review_block`, `protocol_warnings`).
  - The protocol-error and warning labels (`status_line_missing`, `status_token_invalid`, `report_unreadable`, `concerns_block_missing`) and their meaning.
  - An explicit note that workflow-specific routing (whether `DONE_WITH_CONCERNS` triggers a wave-level checkpoint, a verifier gate, an immediate proceed, etc.) is owned by each caller's SKILL.md, not by this contract.
- Add `packages/pi-flow-core/skills/_shared/idea-closure.md` describing the linked-idea-closure procedure parameterized by `(idea_id, completion_note)`:
  - Caller resolves its own idea ID via its own source-lookup rule (the two existing rules stay caller-local).
  - Caller supplies its own completion-note string.
  - Shared procedure owns: `idea` tool `action: "read"` of the resolved ID; skip silently when the idea is missing, unreadable, or already `closed`; otherwise `idea` tool `action: "update"` with `status: "closed"` and `body: "<existing body + \n<completion_note>>"`.
  - The doc is markdown-only (no Python helper); the orchestrator drives the built-in `idea` tool.

Skill updates:

- Update `packages/pi-flow-core/skills/fastlane/SKILL.md`:
  - Step 4 `{TDD_BLOCK}` placeholder source changes from `skills/execute-plan/tdd-block.md` to `skills/_shared/coder-tdd-block.md`.
  - Step 5 parser call changes from `pi-flow helper execute-plan/parse-coder-report` to `pi-flow helper _shared/parse-coder-report`.
  - Step 5's "Route on `.status`, mirroring `skills/execute-plan/SKILL.md` Step 9" becomes a reference to `skills/_shared/coder-report-contract.md`. Fastlane's local routing language — the four-row status table, the `DONE_WITH_CONCERNS` checkpoint block, the `NEEDS_CONTEXT` retry rule, the `BLOCKED` immediate-stop block — stays in fastlane unchanged.
  - Step 10's "Mirror `skills/execute-plan/SKILL.md` Step 16.2:" becomes a reference to `skills/_shared/idea-closure.md` invoked with fastlane's own `idea_id` resolution (input idea or spec-preamble extraction) and fastlane's own `completion_note` (`Completed via fastlane: <commit SHA>, spec: <spec path>` or `spec: (input was idea)`).
- Update `packages/pi-flow-core/skills/execute-plan/SKILL.md`:
  - Step 8's helper-invocation line continues to call `pi-flow helper execute-plan/assemble-coder-prompt`; the wording about which TDD block file is inlined updates to reflect the relocated `_shared/coder-tdd-block.md` source.
  - Step 9 references `skills/_shared/coder-report-contract.md` for the parser invocation and status semantics. The parser call changes from `pi-flow helper execute-plan/parse-coder-report` to `pi-flow helper _shared/parse-coder-report`. Execute-plan's local routing — the wave-gate blocked/concerns handling in Step 10, the verifier gate in Step 11, etc. — stays in `execute-plan/SKILL.md` unchanged.
  - Step 16.2 references `skills/_shared/idea-closure.md` invoked with execute-plan's own `idea_id` resolution (`**Source:** IDEA-<id>` scan of the plan body) and its own `completion_note` (`Completed via plan: docs/plans/<plan-filename>.md`).
- Update `packages/pi-flow-core/skills/execute-plan/scripts/assemble-coder-prompt.py`:
  - The `default_tdd_block_template` path changes to point at `skills/_shared/coder-tdd-block.md` (the script lives at `skills/execute-plan/scripts/`, so the relative walk needs to traverse up two levels and across into `_shared/`).
  - The `--tdd-block-template` help text continues to reference the default by its new path.
- Update `packages/pi-flow-core/skills/execute-plan/scripts/tests/test_assemble_coder_prompt.py`:
  - The fixture path constant currently referencing `tdd-block.md` (around line 24) updates to follow the relocated `_shared/coder-tdd-block.md`.

Post-conditions on the filesystem:

- `packages/pi-flow-core/skills/execute-plan/tdd-block.md` no longer exists.
- `packages/pi-flow-core/skills/execute-plan/scripts/parse-coder-report.py` no longer exists.
- The seven `coder-report-*.md` fixtures no longer exist under `skills/execute-plan/scripts/tests/fixtures/`.
- `packages/pi-flow-core/skills/execute-plan/scripts/tests/test_parse_coder_report.py` no longer exists.
- The new shared files (`coder-tdd-block.md`, `coder-report-contract.md`, `idea-closure.md`, `scripts/parse-coder-report.py`, the relocated fixtures, the relocated `test_parse_coder_report.py`) exist under `skills/_shared/`.

## Constraints

- No compatibility shim at `skills/execute-plan/scripts/parse-coder-report.py`. The two call sites are flipped atomically in the same change so the helper-resource-ID transition has no overlap window.
- The shared docs (`coder-report-contract.md`, `idea-closure.md`, `coder-tdd-block.md`) MUST stay small and contract-focused. They MUST NOT grow into another workflow skill. Each new `_shared/*.md` follows the size and tone of the existing files (`coordinator-dispatch.md` is ≈25 lines; `test-runner-dispatch.md` is similar) — short prose, focused contract, no workflow procedure.
- Workflow-specific behavior — Fastlane's status-routing menus and verbatim checkpoint blocks, execute-plan's wave-gate concerns handling, each skill's idea-source-lookup rule, each skill's completion-note text — stays in the respective SKILL.md. The shared docs document the common substrate (parser invocation, output schema, status semantics; idea-closure tool-call sequence), not the workflow.
- The parser helper's behavior is preserved byte-for-byte: same CLI flags, same stdout JSON shape, same stderr JSON shape, same exit codes, same protocol-error and warning labels. Only the resource ID (`pi-flow helper execute-plan/parse-coder-report` → `pi-flow helper _shared/parse-coder-report`) and the file location change.
- The helper-runner resolution surface in `bin/pi-flow.mjs` is unchanged; the move uses the existing `<location>/<name>` lookup convention.
- The set of plan-specific assets that does NOT move is explicit: `extract-plan-tasks.py`, `assemble-coder-prompt.py`, `assemble-verifier-prompt.py`, `parse-verifier-report.py`, `compute-verifier-file-set.py`, `collect-diff-context.py`, `execute-task-prompt.md`, `verify-task-prompt.md`, `acceptance-criteria-verification.md`, `integration-regression-debugging.md`, `integration-regression-gate.md`. These stay in `skills/execute-plan/`.

## Acceptance Criteria

- `packages/pi-flow-core/skills/fastlane/SKILL.md` contains zero occurrences of: the literal path prefix `skills/execute-plan/`; the resource ID `pi-flow helper execute-plan/parse-coder-report`; any phrase mirroring an `execute-plan` step number for status routing or idea closure (e.g., `mirroring skills/execute-plan/SKILL.md Step 9`, `Mirror skills/execute-plan/SKILL.md Step 16.2`).
- `packages/pi-flow-core/skills/fastlane/SKILL.md` does reference `skills/_shared/coder-tdd-block.md` at its `{TDD_BLOCK}` source, `pi-flow helper _shared/parse-coder-report` at its parser call, `skills/_shared/coder-report-contract.md` at its status-routing entry, and `skills/_shared/idea-closure.md` at its linked-idea-closure step.
- `packages/pi-flow-core/skills/execute-plan/SKILL.md` references the same four shared assets at its corresponding sites (Step 8 TDD block, Step 9 parser + contract, Step 16.2 idea closure).
- The new shared files exist with the content described in Requirements: `skills/_shared/coder-tdd-block.md`, `skills/_shared/coder-report-contract.md`, `skills/_shared/idea-closure.md`, `skills/_shared/scripts/parse-coder-report.py`, and the relocated `skills/_shared/scripts/tests/fixtures/coder-report-*.md` + `skills/_shared/scripts/tests/test_parse_coder_report.py`.
- `skills/execute-plan/tdd-block.md`, `skills/execute-plan/scripts/parse-coder-report.py`, `skills/execute-plan/scripts/tests/test_parse_coder_report.py`, and the seven relocated `coder-report-*.md` fixtures under `execute-plan/scripts/tests/fixtures/` no longer exist.
- Running `pi-flow helper _shared/parse-coder-report --report <fixture>` against each relocated fixture produces stdout/stderr that is byte-equal to what the pre-move `pi-flow helper execute-plan/parse-coder-report` produced for the same fixture.
- `pnpm test:helpers` (run from `packages/pi-flow-core/`) passes, including the relocated `test_parse_coder_report.py` discovered under `skills/_shared/scripts/tests/` and the updated `test_assemble_coder_prompt.py` under `skills/execute-plan/scripts/tests/`.
- `pnpm check` (typecheck + node tests + helper tests) passes after the refactor with no other test changes required.
- A manual read of both updated SKILL.md files shows the workflow-specific routing language preserved verbatim in each skill (fastlane's four-row status table and checkpoint blocks; execute-plan's Step 10 wave gate, Step 11 verifier gate, Step 16.2 lookup rule).

## Non-Goals

- De-duplicating the coder-facing `## Report Format` section between `skills/fastlane/fastlane-coder-prompt.md` and `skills/execute-plan/execute-task-prompt.md`. Considered during scope discussion and deliberately deferred — the current change targets internal workflow coupling, not coder-prompt content. The two prompt templates remain independently authored.
- Adding a guardrail test that asserts `fastlane/SKILL.md` has no references to `execute-plan` internals. Considered and rejected in favor of code review enforcement; the repo's other cross-skill contracts (`_shared/coordinator-dispatch.md`, `_shared/test-runner-dispatch.md`) are not backed by drift-detection tests on their callers, and a string-pattern test on SKILL.md content would create churn on unrelated edits.
- Introducing a Python helper for the linked-idea-closure procedure. The shared `idea-closure.md` is markdown-only; the orchestrator continues to drive the built-in `idea` tool directly.
- Moving plan-specific assets out of `skills/execute-plan/`: `extract-plan-tasks.py`, `assemble-coder-prompt.py`, `assemble-verifier-prompt.py`, `parse-verifier-report.py`, `compute-verifier-file-set.py`, `collect-diff-context.py`, `execute-task-prompt.md`, `verify-task-prompt.md`, `acceptance-criteria-verification.md`, `integration-regression-debugging.md`, `integration-regression-gate.md`.
- Changing parser behavior, status names, protocol-error labels, or warning labels of `parse-coder-report.py`. The move is byte-for-byte behavior-preserving.
- Reorganizing fastlane's or execute-plan's overall workflow steps; only the four enumerated reference sites in each SKILL.md change.
