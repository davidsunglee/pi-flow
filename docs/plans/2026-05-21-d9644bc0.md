# Rebrand workflow artifacts from TODO-<id> to IDEA-<id>

**Source:** `IDEA-d9644bc0`
**Spec:** `docs/specs/2026-05-21-d9644bc0.md`
**Scout brief:** `docs/briefs/TODO-d9644bc0-brief.md`

## Goal

Replace the legacy `TODO-<id>` / `docs/todos/` terminology and identifier shape throughout `pi-flow-core` with `IDEA-<id>` / `docs/ideas/`, drop every code path that recognized or emitted `TODO-`, and remove the runtime dependency on the external `todo` tool by routing all idea-artifact state access through the built-in `idea` tool. This is a single coordinated changeset with no compatibility window — users migrate their on-disk artifacts via a one-time `mv docs/todos docs/ideas`, which is documented but not executed by this work.

## Architecture summary

The rebrand spans three coordinated layers in `packages/pi-flow-core/`:

1. **TypeScript extension surface** (`extensions/storage.ts`, `extensions/idea.ts`, `extensions/router.ts`, `extensions/workflow.ts`) — the runtime that registers `/flow:idea`, the `idea` tool, the workflow slash commands, and the artifact-token router. Storage path resolution moves from `docs/todos/` to `docs/ideas/`, `normalizeIdeaId` strips only `IDEA-`, `router.ts`'s `TODO_RE` becomes `IDEA_RE` and recognizes `IDEA-<8hex>` / bare hex, all user- and LLM-visible strings emit `IDEA-<id>`, and `isLegacyTodoId` is deleted.

2. **Python helper + provenance chain** (`skills/_shared/scripts/extract-provenance-preamble.py`, the `prepare-plan-*.py` helpers, the `fill-refine-plan-prompt.py` helper, and their tests + fixtures) — the parser that scans spec/plan preambles for `Source: <id>` becomes `IDEA-`-only and emits a renamed `source_idea` JSON field. Every downstream consumer renames its CLI flag from `--source-todo` to `--source-idea` and its placeholder token from `{SOURCE_TODO}` to `{SOURCE_IDEA}`, in lockstep.

3. **Skill prose + agent docs** (`skills/scout`, `skills/define-spec`, `skills/generate-plan`, `skills/refine-plan`, `skills/execute-plan`, `skills/fastlane`, `agents/planner.md`) — the markdown that drives orchestrator and subagent behavior. Skill-level access to idea artifacts (read body, read status, update status, append to body) is routed through the built-in `idea` tool's `read` and `update` actions in `generate-plan`, `execute-plan`, `fastlane`, AND `scout` — the external `todo` tool is no longer referenced anywhere. Input-detection regexes flip to `^IDEA-[0-9a-f]{8}$`, brief paths flip to `docs/briefs/IDEA-<id>-brief.md`, test-run directories flip to `docs/test-runs/IDEA-<id>/`, plan header emits `**Source:** IDEA-<id>`, and the `_shared` tool-availability table in `execute-plan` Step 9 drops the `todo tool` row.

Cross-cutting: `skills/_shared/workflow-artifact-paths.md` allowlist replaces `docs/todos/` with `docs/ideas/`, propagating into `classify-workflow-drift.py` tests. The `README.md` documents the rebrand, rationale, and the one-time `mv docs/todos docs/ideas` user migration. Existing on-disk artifacts in `docs/todos/` are left untouched — the user runs the `mv` themselves.

## Tech stack

- **Languages:** TypeScript (ESM, `--experimental-strip-types`), Python 3 (stdlib only).
- **Runtime:** Node.js `--test` for TS, Python `unittest` for helpers.
- **Frameworks:** `@earendil-works/pi-coding-agent` (extension/tool/command registration), `typebox` (tool parameter schemas).
- **Build / test:** `pnpm test` at workspace root (delegates to `pnpm run test:node && pnpm run test:helpers` in `packages/pi-flow-core/`).

## Risk Assessment

1. **Cutover atomicity.** The spec's central constraint is a single coordinated changeset — partial updates silently break the provenance chain (e.g., writer emits `IDEA-` while a reader still requires `TODO-`). The dependency graph above is the safeguard: Task 12 (generate-plan prose calling `source_idea`) cannot land before Task 6 (parser renames `source_todo` → `source_idea`), or generate-plan will read a `null` field at runtime. Mitigation: every reviewer pass should re-run Task 19's repo-wide greps to confirm no `TODO-` / `source_todo` / `SOURCE_TODO` leaks remain.

2. **Test fixture sharing.** `preamble-spec-clean.md` and `preamble-spec-fenced-heading.md` are shared across multiple tests in `test_extract_provenance_preamble.py`. Task 6 updates them in place; if a test asserts a literal `TODO-` value that we miss, the test will fail. Mitigation: Task 6 Step 6 itemizes every test case that needs updating; review each method against the fixture content after the edit.

3. **Scout title-fallback semantics.** Task 11's switch from inline JSON parsing to `idea` tool `details` payload changes the fallback order subtly: previously the scout skill read the JSON metadata block from disk (parsing it inline); now it consumes the parsed `details` object. Mitigation: the spec preserves "JSON metadata block first, then first `# ` heading outside fences, then explicit failure"; the rewrite must keep the fence-aware H1 fallback in prose so the skill still describes a deterministic behavior even when `details.title` is empty.

4. **Empty title from `idea` tool.** The `idea` tool's `details.title` field always carries the value from the JSON metadata block. If the metadata's `title` is an empty string, the tool's `readIdea` succeeds (returns the artifact with `title: ""`), but the scout skill's title-fallback must then fire. The current `parseIdeaArtifact` rejects artifacts where `typeof meta.title !== "string"` (so missing title is rejected) but accepts empty strings. Task 11's rewrite preserves the H1 fallback explicitly so an empty-title artifact still gets a name from its body.

5. **`router.ts` matrix property rename.** The `EXACT_INPUT_MATRIX`'s `todoId` boolean is renamed to `ideaId` in Task 3. Any external consumer importing this matrix would break. Grep confirms only `router.ts` itself reads the property; no other module destructures it. Mitigation: Task 3 Step 3 explicitly grep-verifies; Task 4's `workflow.ts`/`workflow.test.ts` don't reference the matrix property directly (they go through `routeArgs`).

6. **`PI_TODO_PATH` / `PI_IDEA_PATH` environment variable.** The spec explicitly says no env-var support is added. `storage.ts:getTodoDir` currently uses no env var, so this is a non-change — the rename to `getIdeaDir` preserves the env-var-free behavior. Documented for future maintainers in the README's migration section.

7. **Brief-path back-compatibility.** Specs and plans on disk that reference `docs/briefs/TODO-<id>-brief.md` will no longer resolve under the new regex/path conventions. The spec explicitly accepts this as out of scope (the user can manually update or treat affected artifacts as historical). README documents the consequence.

8. **`isLegacyTodoId` deletion.** The brief notes the function is exported but unused in this package, and recommends auditing external consumers before deleting. Grep at the workspace root (`grep -rn 'isLegacyTodoId' /Users/david/Code/pi-flow/`) returns only `storage.ts`, `storage.test.ts`, and the spec/brief files — no external consumer. Safe to delete (Task 1 Step 4 + Task 1 Step 5).

9. **Test-runner artifact filename collisions.** Task 15 (fastlane) and downstream test-run flows use `docs/test-runs/<spec-name-or-IDEA-<id>>/`. If a user has an in-progress fastlane run with the old `docs/test-runs/TODO-<id>/` directory layout, that run's artifacts won't conflict with a new run (different directory names), but the user must clean up the old directory manually. Documented implicitly by the README's broader "hard cutover" framing.

10. **Re-use of the `{TODO_BODY_OR_FREEFORM_TEXT}` placeholder name in scout.** Task 11's switch to the `idea` tool changes the *source* of the value but not the placeholder name; the scout-prompt.md template still uses `{TODO_BODY_OR_FREEFORM_TEXT}`. The placeholder name is a downstream implementation detail not visible to users; renaming it would be a churn-only change with no protocol benefit. Mitigation: the placeholder stays as-is (and Task 11 Step 2's prose explicitly notes "the placeholder name is retained; only the source of its value changes").
