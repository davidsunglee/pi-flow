# Prepare pi-flow packages for npm publication under @aphotic

**Goal:** Rename the three workspace packages to `@aphotic/pi-flow`, `@aphotic/pi-flow-core`, and `@aphotic/pi-flow-ux`, set version `0.5.0`, remove `private: true`, add npm metadata (license, repository, engines, publishConfig), create LICENSE files, tighten peer dependency ranges, trim test fixtures from the core tarball, update all internal references and tests to use scoped names, and add packlist regression tests and release documentation.

**Architecture summary:** This is a publication-preparation refactor with no new runtime features. Changes fall into five layers: (1) package.json identity/metadata edits across all four manifests, (2) internal reference updates in the aggregate bin wrapper, `pi` manifest paths, documentation, and help text, (3) existing test updates to assert scoped names and paths, (4) new packlist regression tests verifying `pnpm pack --dry-run` output, and (5) release documentation. The workspace root stays `private: true` and retains its unscoped `pi-flow-workspace` name.

**Tech stack:** Node.js >=20, pnpm workspaces, ESM (`"type": "module"`), `node:test` test runner

## Risk Assessment

- **pnpm workspace relinking after rename:** After renaming packages from unscoped to scoped names, `pnpm install` must re-create the workspace symlinks under `node_modules/@aphotic/`. If this fails, all downstream tests and the aggregate bin wrapper will break. **Mitigation:** Task 1 Step 5 explicitly runs `pnpm install` and verifies linkage before any tests execute.

- **`files` negation pattern semantics:** pnpm/npm `files` array negation patterns (`!**/tests`) may behave differently across npm versions. The `**` glob must match nested test directories under `skills/`. **Mitigation:** Task 5 includes a dedicated packlist regression test that verifies the exact files included in `pnpm pack --dry-run` output. If the negation patterns don't work as expected, the test will catch it immediately.

- **Aggregate `pi` manifest path resolution:** After renaming dependencies, the aggregate's `pi.skills`, `pi.extensions`, and `pi.themes` paths change from `node_modules/pi-flow-core/...` to `node_modules/@aphotic/pi-flow-core/...`. If pnpm's workspace linking creates the symlink at a different path structure, the Pi loader will fail to discover resources. **Mitigation:** The existing aggregate-forwarding test (Task 4) verifies path resolution and will catch mismatches.

- **`workspace:*` rewrite on publish:** When pnpm publishes, it rewrites `workspace:*` to concrete versions. After renaming to scoped names, the rewritten dependency keys must be `@aphotic/pi-flow-core` and `@aphotic/pi-flow-ux`. **Mitigation:** Task 8 Step 3 explicitly verifies the packed manifest after packing.
