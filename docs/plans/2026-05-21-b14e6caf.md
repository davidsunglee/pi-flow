# Restore Flow Ideas UX Parity with the Old Todos Tool

**Source:** `IDEA-b14e6caf`
**Spec:** `docs/specs/2026-05-21-b14e6caf.md`

## Goal

Bring the `idea` / `IDEA-<id>` surface back to parity with the old `todo` / `TODO-<id>` UX: ship a `/flow:ideas` TUI browser/manager over `docs/ideas/*.md`, expand the `idea` tool API (`list / read / create / update / append / delete` with filtered `list`), add custom transcript renderers, teach the LLM to author bodies in the canonical 5-section shape via `description` + `promptSnippet`, normalize the on-disk status enum to `"open" | "closed"` while remaining read-tolerant of legacy `"done"`, and preserve every Flow-specific semantic (`IDEA-<id>` only, `docs/ideas/<id>.md` only, durable artifacts — no GC, no claim/release, no lock files).

## Architecture summary

All TypeScript changes land in two existing files in `packages/pi-flow-core/extensions/`:

1. **`storage.ts` — schema, parser, file I/O, list filtering.** The `IdeaArtifact.status` field becomes `"open" | "closed"` (post-normalization). `parseIdeaArtifact` accepts `"open" | "done" | "closed"` and normalizes legacy `"done"` to `"closed"`. Unknown JSON fields are ignored. `writeIdea` always serializes `"closed"`. `listIdeas` is extended to optionally accept `{ status?, query? }` filters and returns richer per-entry rows including `tags` and `createdAt` (zero-arg callers keep working). Two new helpers are added: `appendIdeaBody(dir, id, body)` (atomic read-modify-write that joins existing + new body with a blank-line separator unless the existing body is empty) and `deleteIdea(dir, id)` (read-then-unlink, returns the deleted record).

2. **`idea.ts` — tool API, slash commands, TUI, renderers, refine prompt.** The spec forbids splitting this file, so it grows in place. New surface:
   - The `idea` tool's `parameters` schema gains `append` and `delete` actions, a `query` field, and an `"all"` status literal. Six action branches dispatch from a single `executeIdeaTool` driver.
   - Custom `renderCall` / `renderResult` callbacks (compact call line; grouped/expandable list result; single-idea result with `✓ Verb` prefix for mutating actions).
   - `description` and `promptSnippet` rewritten to teach the LLM the canonical 5-section body shape.
   - New `flow:ideas` slash command. Without UI, prints a grouped text list (Open ideas / Closed ideas). With UI, opens a TUI built from injected pi-tui primitives (`Container`, `SelectList`, `Input`, `Markdown`, `Spacer`, `Text`, `DynamicBorder`).
   - TUI components implemented as private classes in `idea.ts`: `IdeaSelectorComponent` (search input + filtered list + hint line + quick keys), `IdeaActionMenuComponent` (top-level menu with 5 items), `IdeaWorkSubmenuComponent` (4 workflow items), `IdeaOtherSubmenuComponent` (3 items), `IdeaDeleteConfirmComponent` (yes/no), `IdeaDetailOverlayComponent` (markdown overlay with scroll). The wrapper passed to `ctx.ui.custom()` swaps an `activeComponent` reference so that opening a menu / submenu / overlay / confirm and dismissing it returns to the right parent without recreating the selector.
   - `buildRefineIdeaPrompt(id, title)` produces the multi-line refine handoff (used by the `refine` action and the `Ctrl+Shift+R` quick key). All TUI handoffs prefill the editor via `ctx.ui.setEditorText(...)`; none auto-send.

Two existing skill prose files (`skills/execute-plan/SKILL.md`, `skills/fastlane/SKILL.md`) and one integration test (`__tests__/idea-tool-only.test.mjs`) are updated to discriminate on `"closed"` instead of `"done"`, in line with the schema migration. The `commands.test.ts` snapshot adds `flow:ideas` and bumps the registered-command count from 9 to 10.

## Risk Assessment

- **Risk: `idea.ts` grows large** — adding six tool branches, four+ TUI components, renderers, and helpers in a single file produces a ~1500–2000 LOC module. The spec explicitly forbids splitting into `extensions/idea/`. Mitigation: structure the file with clear section comments (`// === Storage helpers and types ===`, `// === Tool execution ===`, `// === Renderers ===`, `// === Helpers ===`, `// === TUI components ===`, `// === Command handlers ===`); export an `_internalsForTest` named export to allow unit tests to reach the internals without splitting the file. Reviewers should expect a longer-than-typical file; this is an explicit acceptance of the spec's constraint.

- **Risk: legacy `"done"` files re-serialize as `"closed"` on read-only operations** — the spec says rewrites happen only on mutation, but `writeIdea` is also called by `appendIdeaBody`, `update`, `create`. Any user opening an old `"done"` file in the TUI and then taking the `close` action against a different idea won't migrate the original. This is intentional per the spec ("No proactive migration commit is required"), but a reader of `docs/ideas/` may be confused by mixed `"done"` / `"closed"` files in source control until each is touched. Mitigation: documented behavior; tests assert the read tolerance explicitly. No code change required.

- **Risk: `fuzzyMatch` semantics differ from `fuzzyFilter`** — pi-tui's `fuzzyFilter` returns a sorted array; we deliberately don't use it because we need a custom sort (status group first, then chronological / score). Calling `fuzzyMatch(token, corpus)` directly per token gives us the per-token gate AND the score, which we sum. The spec is explicit: "Multi-token fuzzy match via pi-tui's fuzzyMatch; each token must match for the item to qualify, with scores summed for ranking." Mitigation: tests in Task 4 cover the empty-query and matching-query orderings.

- **Risk: `ctx.ui.custom` callback signature** — the wrapper passed to `ctx.ui.custom` must return an object with `{ render, invalidate, handleInput }`. Component swapping inside the wrapper requires that each new "active component" still has those three methods. The TUI components in Tasks 6–8 implement `Component` from pi-tui which already exposes those. Mitigation: use the documented pattern from `examples/extensions/preset.ts` (lines 252-262) — the wrapper holds an `activeComponent` reference and delegates the three methods to it.

- **Risk: command count assertion drift** — `commands.test.ts` hard-asserts `commands.size === 9` and a specific ordered array. Adding `flow:ideas` to the order is the only safe path; otherwise the test fails. Mitigation: Task 5 explicitly updates this test alongside the registration.

- **Risk: existing `idea.test.ts` `tool list returns seeded ideas` test** — the current test seeds one open and one `"done"` (which becomes `"closed"`) idea and expects both back, but the new default filter is `status: "open"`, so the default `list` will only return one. Task 2 explicitly rewrites this test to either pass `status: "all"` or split into two assertions (default returns only open; `"all"` returns both). Without that rewrite, `pnpm test` fails after Task 1. Mitigation: Task 2 Step 12 covers this.

- **Risk: `IdeaSelectorComponent.handleInput` colliding with the printable-character search path** — the spec's hint line includes characters like `r`, `f`, `s` that the search input also accepts. Mitigation: the quick-key matchers use `Key.ctrlShift("R")` etc., which require both modifiers; plain `r` falls through to the search-input append branch. The matcher order in Task 6 Step 4 places the quick-key matchers BEFORE the printable-char append branch, ensuring this dispatch is unambiguous.

- **Risk: `view` action requires a fresh `readIdea` because the selector only has `IdeaListEntry` (no body)** — the action menu is opened from the selector with an `IdeaListEntry`, but the detail overlay needs the full body. Task 9 Step 4 reads the full artifact via `readIdea(dir, idea.id)` before opening the overlay, and notifies if the file has been deleted since the listing snapshot. Mitigation: explicit `await readIdea` + `if (!full) { ctx.ui.notify(...); return; }` guard.
