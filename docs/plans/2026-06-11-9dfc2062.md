# Plan: Treat a passing test run as an authoritative pass (no false gate-blocks)

**Source:** IDEA-9dfc2062
**Spec:** docs/specs/2026-06-11-9dfc2062.md

## Goal

When a Codex-backed `test-runner` subagent runs a suite that passes (`EXIT_CODE: 0`) but non-deterministically misclassifies it — pasting passing output into `NON_RECONCILABLE_FAILURES` (or listing bogus entries under `FAILING_IDENTIFIERS`) — the deterministic reconcile layer currently honors those buckets and false-blocks the integration gate. This work adds one semantic invariant at the shared parser chokepoint: **a structurally valid artifact reporting `EXIT_CODE: 0` is an authoritative pass**, so both buckets are discarded (overridden to empty) and reconcile classifies the run `clean`/`pass`. The override is non-silent — the parser emits a flag plus the discarded counts/contents, and the dispatch contract surfaces a one-line caller warning analogous to the existing `used_fallback` warning. A non-zero `EXIT_CODE` retains today's behavior exactly.

## Architecture summary

The integration gate runs a fixed deterministic pipeline already in place:

```
test-runner subagent (LLM, writes artifact)
        │  artifact file on disk
        ▼
parse-test-runner-artifact.py   ← structural validator + parser → JSON   ★ chokepoint
        │  (reconcile-test-run.py calls this as a subprocess; the
        │   test-runner-dispatch.md "validate + parse" step calls it directly)
        ▼
reconcile-test-run.py           ← capture (baseline) / reconcile (gate) classifier
        │  JSON with classification
        ▼
execute-plan SKILL steps 7 / 12.2 / 16 (render summary, gate)
```

The fix lands at the single chokepoint — `parse_artifact()` in `parse-test-runner-artifact.py` — **after** all existing structural validation passes. Because `reconcile-test-run.py` consumes the parser's JSON output, and `test-runner-dispatch.md`'s validate-and-parse step also calls the parser directly, every consumer (baseline capture, wave reconcile, final gate, dispatch validation) inherits the invariant uniformly with no change to reconcile's classification logic. `reconcile-test-run.py` is changed only to *propagate the override signal* into its own output so callers can warn; its `clean`/`pass` result for a passing run falls out automatically because the buckets it reads are already empty.

Override semantics (applied only when `exit_code == 0` AND at least one bucket is non-empty):

- `failing_identifiers` → `[]`, `failing_identifiers_count` → `0`
- `non_reconcilable_failures` → `[]`, `non_reconcilable_count` → `0` (keeps the parser's `count == len(list)` invariant intact)
- Add conditional audit fields: `exit0_override: true`, `discarded_failing_identifiers_count`, `discarded_non_reconcilable_count`, `discarded_failing_identifiers`, `discarded_non_reconcilable_failures`

**Open-question resolution (spec §Open Questions):** retain the discarded bucket *contents* as audit fields, not just a boolean + counts. The data is already parsed; retaining it is free, makes repeated Codex misclassification directly diagnosable from the JSON without re-parsing the raw artifact, and is emitted only when the override fires.

**Conditional emission is load-bearing:** the new keys appear **only** when the override fires. When the exit code is non-zero, or it is `0` with already-empty buckets, the parser output is byte-for-byte unchanged from today. This is what keeps the pre-existing `TestSuccessJsonShape` exact-key-set assertion (which uses an `EXIT_CODE: 1` artifact) passing untouched, and directly satisfies the "no signal when not fired" acceptance criterion.

```python
def _apply_exit0_override(result):
    """Treat EXIT_CODE 0 as an authoritative pass.

    The test-runner contract declares exit-0 implies both buckets empty, but
    Codex intermittently emits a structurally valid artifact reporting
    EXIT_CODE 0 with non-empty buckets (observed 2026-06-09: passing stdout
    copied into NON_RECONCILABLE_FAILURES). Such an artifact would otherwise
    false-block the integration gate. When the exit code is 0 and either bucket
    is non-empty, discard the contradictory buckets (and zero their counts so
    the count == len(list) invariant holds) and expose the override via a flag,
    the discarded counts, and the discarded contents for audit. A non-zero exit
    code is left untouched.
    """
    if result["exit_code"] != 0:
        return result
    if not result["failing_identifiers"] and not result["non_reconcilable_failures"]:
        return result
    result["exit0_override"] = True
    result["discarded_failing_identifiers_count"] = result["failing_identifiers_count"]
    result["discarded_non_reconcilable_count"] = result["non_reconcilable_count"]
    result["discarded_failing_identifiers"] = result["failing_identifiers"]
    result["discarded_non_reconcilable_failures"] = result["non_reconcilable_failures"]
    result["failing_identifiers"] = []
    result["failing_identifiers_count"] = 0
    result["non_reconcilable_failures"] = []
    result["non_reconcilable_count"] = 0
    return result
```

```python
def _attach_override_signal(result, parsed):
    """Propagate the parser's exit-0 override signal into the reconcile output.

    The parser already discarded the contradictory buckets, so classification
    needs no change; this only surfaces the signal (flag + discarded counts) so
    the caller can warn. Fields are added only when the override fired.
    """
    if parsed.get("exit0_override"):
        result["exit0_override"] = True
        result["discarded_failing_identifiers_count"] = parsed.get(
            "discarded_failing_identifiers_count", 0
        )
        result["discarded_non_reconcilable_count"] = parsed.get(
            "discarded_non_reconcilable_count", 0
        )
    return result
```

## Risk Assessment

- **Breaking the pre-existing `TestSuccessJsonShape` exact-key-set assertion.** That test asserts the precise key set of the parser output on an `EXIT_CODE: 1` artifact. Mitigation: the override fields are emitted **conditionally** (only when `exit_code == 0` and a bucket is non-empty), so a non-zero-exit artifact's key set is unchanged. Verified: every existing fixture/inline artifact with non-empty buckets has a non-zero exit (`stable-failures` = 1, `count-mismatch` = 1, `non-reconcilable` = 2, inline `TestSuccessJsonShape`/`TestDuplicateIdentifierDedupes` = 1), and every existing exit-0 artifact (`clean`, `no-phase`, inline `CLEAN_ARTIFACT`) has empty buckets — so none trigger the override.
- **Capture-mode output is re-consumed as a baseline file.** `reconcile-test-run.py --mode capture` output is written to `baseline-failures.json` and later read by reconcile's `_load_baseline`. Adding `exit0_override`/`discarded_*` keys could in principle confuse that reader. Mitigation: `_load_baseline` reads only `failing_identifiers` / `baseline_failures` and ignores all other keys; the extra fields are inert. A passing baseline correctly records `baseline_failures: []`.
- **Count/list invariant drift.** Leaving a non-zero `non_reconcilable_count` while emptying its list would violate the parser's `count == len(list)` guarantee that downstream code may assume. Mitigation: the override zeroes both counts alongside emptying both lists; the declared originals are preserved in `discarded_*_count`.
- **Over-broad override swallowing a real failure.** The override fires only on `exit_code == 0`. A real failing suite returns non-zero, so genuine failures (including non-reconcilable crashes/build errors) are never discarded — guarded by `test_nonzero_exit_buckets_honored_no_signal` (parser) and `test_reconcile_nonzero_exit_still_fails_no_signal` (reconcile). This matches the spec constraint that non-zero-exit behavior is unchanged.
- **Composite-entry fixture validity.** The regression fixture's `NON_RECONCILABLE_FAILURES` block contains internal blank lines with `NON_RECONCILABLE_COUNT: 1`. If the `expected_count == 1` composite-collapse rule were misremembered, the fixture could fail `non_reconcilable_count_mismatch` before reaching the override. Mitigation: confirmed against `_split_non_reconcilable_entries` (lines 93–115 of the parser) — with `expected_count == 1` and multiple blank-separated groups, it returns a single `"\n".join(lines)` entry, so the count reconciles and the artifact is structurally valid (the exact path the 2026-06-09 artifact exercised).
