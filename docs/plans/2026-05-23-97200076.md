# Decouple fastlane from execute-plan internals

**Source:** IDEA-97200076
**Spec:** docs/specs/2026-05-23-97200076.md

## Goal

Eliminate `fastlane`'s reliance on `execute-plan` internal files, helpers, and mirrored step-number references by relocating the reusable primitives (`tdd-block.md`, `parse-coder-report.py`, the parser's fixtures and tests) into `skills/_shared/`, replacing the mirrored-language references with two new small contract-style docs (`coder-report-contract.md`, `idea-closure.md`), and flipping both call sites (`fastlane/SKILL.md`, `execute-plan/SKILL.md`) to the new shared resource IDs in the same change. The parser's behavior, CLI surface, exit codes, and protocol-error labels are preserved byte-for-byte; only the file location and helper resource ID change.

## Architecture summary

The current coupling is replaced by a small `_shared/` substrate that both skills consume:

- **Shared markdown contracts** (added): `skills/_shared/coder-report-contract.md` documents the parser invocation and the four valid statuses; `skills/_shared/idea-closure.md` documents the `(idea_id, completion_note)`-parameterized closure procedure driven by the built-in `idea` tool.
- **Shared coder TDD block** (moved): `skills/_shared/coder-tdd-block.md` replaces `skills/execute-plan/tdd-block.md`; the content is workflow-neutral and stays unchanged.
- **Shared parser helper** (moved): `skills/_shared/scripts/parse-coder-report.py` replaces `skills/execute-plan/scripts/parse-coder-report.py`. The script's `sys.path.insert(...)` line that imports `fence_aware` shortens (it now lives in the same `scripts/` directory as `fence_aware.py`). Resource ID flips from `execute-plan/parse-coder-report` to `_shared/parse-coder-report` via the existing `pi-flow.mjs` lookup convention. Fixtures and tests move alongside.
- **Two call-site updates**: `fastlane/SKILL.md` and `execute-plan/SKILL.md` flip their references to the new shared paths atomically. Workflow-specific routing language (fastlane's status table and checkpoint blocks; execute-plan's Step 10 wave gate, Step 11 verifier gate, Step 16.2 idea-source-lookup rule) stays caller-local; only the four enumerated reference sites in each SKILL.md change.

## Tech stack

- Python 3 (helper scripts under `skills/_shared/scripts/` and `skills/execute-plan/scripts/`)
- Node.js (`packages/pi-flow-core/bin/pi-flow.mjs` resolves `<location>/<name>` helper IDs to script paths)
- Markdown (SKILL.md workflow docs and `_shared/*.md` contract docs)
- TypeScript (`packages/pi-flow-core/scripts/run-helper-tests.ts` discovers test suites under `skills/*/scripts/tests/`)
- pnpm workspace at the project root; helper tests run via `pnpm test:helpers` from `packages/pi-flow-core/` and via `pnpm check` from the project root.
