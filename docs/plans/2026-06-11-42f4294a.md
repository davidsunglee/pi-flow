# Plan: Make /flow:doctor scope-aware with a stable per-cwd helper dispatcher and a readable report

Source: IDEA-42f4294a
Spec: docs/specs/2026-06-11-42f4294a.md

## Goal

Teach `/flow:doctor` to model Pi's effective-package semantics so an installed-but-overridden global pi-flow, or a leftover project install shadowed by the active user package, reads as neutral `[inactive]` inventory rather than resolution `[SKEW]`. Three supporting changes make this durable: (1) extract npm-spec parsing, aggregate↔core identity normalization, effective-package resolution, the trust check, and path abbreviation into a single bare-node `.mjs` module shared by both the dispatcher and the TypeScript extension so the two resolvers can never drift; (2) replace the single-root `~/.pi/agent/bin/pi-flow` symlink with a stable, self-contained dispatcher that resolves the *effective* pi-flow-core root for the current cwd at runtime (honoring a trusted project override, else falling back to the user/global target); (3) rewrite the doctor report into a grouped, status-led layout with aggressive path abbreviation that scans cleanly at any panel width. The read-only / never-delete `--fix` boundary and the never-edit-settings posture are preserved throughout.

## Architecture summary

Doctor lives in `packages/pi-flow-core/extensions/doctor.ts`. It inventories the managed pi-flow surfaces (helper shim, user/project agent symlinks, npm installs, declared packages, node bins), classifies each against a single `activeRoot` (the executing package's realpath), and renders a report via `ctx.ui.notify`. There is **no build step**: Pi loads `.ts` extensions directly under `node --experimental-strip-types`, and `bin/pi-flow.mjs` runs under bare `node`. Therefore the dispatcher **cannot import any `.ts` file** at runtime — all shared logic must be plain `.mjs` with node-builtin imports only.

The central new artifact is **`extensions/lib/effective-package.mjs`** — a bare-node module that becomes the single source of truth for resolution. It owns:

- the resolution primitives currently in `package-resolution.ts` (`realpathOrNull`, `packageRootFromBin`, `readPiFlowCorePackage`, `findEnclosingCoreRoot`) and the `resolveBinToCore` aggregate-delegation logic currently in `doctor.ts`, ported to plain JS;
- **npm-spec parsing**: string form (`"npm:@aphotic/pi-flow"`, `"npm:@aphotic/pi-flow-core"`, pinned `"npm:@aphotic/pi-flow@0.8.0"`), object form (`{ "source": "npm:..." }`), and local/path form — classifying `kind` (`npm`/`local`), extracting package name and any `@<version>` pin;
- **package-identity normalization**: mapping both the aggregate `@aphotic/pi-flow` and the direct `@aphotic/pi-flow-core` to one logical pi-flow identity, and resolving that identity to its concrete `@aphotic/pi-flow-core` root (directly for a core install, via the aggregate wrapper's dependency for an aggregate install, mirroring `resolveBinToCore`'s delegation);
- **effective-package resolution** for a `(cwd, homeDir)`: apply Pi's project-overrides-user rule — a trusted project that declares a pi-flow `packages` entry overrides the user install; otherwise the user/global install is effective;
- **trust check**: read `~/.pi/agent/trust.json` (a `{ "<path-prefix>": true }` map) and return whether a cwd is trusted by exact-or-ancestor key match; missing/malformed ⇒ untrusted;
- **path abbreviation**: `$HOME`→`~`, and elide the predictable install-boilerplate middle (`.../node_modules/@aphotic/<pkg>` → `.../…/<pkg>`).

`package-resolution.ts` and `doctor.ts` are re-pointed to **re-export / call** the `.mjs` (a `.ts` file can import a runtime `.mjs` under strip-types), so no resolution logic is duplicated. `parseDeclaredPackages` moves into the `.mjs` (fixing the string-`npm:` mis-classification) and doctor re-exports the typed wrapper.

Doctor's `buildDiagnosis` gains an **effective model**: before classifying surfaces it computes the effective pi-flow root for `(cwd, homeDir)` via the shared module, keeps the active/executing root from `import.meta.dirname` + `pi.getCommands()` `sourceInfo`, and classifies each surface against both. New classifications `inactive-overridden` (a real install whose identity a higher-priority scope overrides) and `inactive-shadowed` (a real install in a non-effective scope) replace the blanket `stale-skew`. `stale-skew` is reserved for a *resolution* surface (helper shim, agent symlinks, node bin) that resolves to a root that is neither effective, nor a recognized inactive install, nor an in-tree checkout. `hasSkew` counts only resolution-kind `stale-skew`; inactive installs never set it. A `--strict` flag additionally requires every effective resolution surface to resolve to the same root (flagging clean-by-default local-dev divergence).

The **dispatcher** is a new bundled launcher `bin/pi-flow-dispatch.mjs`. `/flow:setup` installs it as a real file copy (not a symlink) at `~/.pi/agent/bin/pi-flow`, so it survives core version changes. At invocation it bootstraps by probing a fixed ordered list of known user-install locations for an importable `effective-package.mjs`, dynamically imports it, calls `resolveEffectiveCoreRoot({ cwd, homeDir })` (which honors a trusted project override), then spawns the resolved core's `bin/pi-flow.mjs` with the original argv (mirroring the current launcher's `spawnSync`/exit-status pattern). It never caches and never crashes on missing/malformed settings or trust — it falls back to the bootstrap user core. Doctor treats the installed dispatcher as a surface, detects staleness by content-comparing it against the active package's bundled `bin/pi-flow-dispatch.mjs`, and re-copies it under `--fix`.

### Decisions settled here (resolving the spec's Open Questions)

- **Single spec, single PR.** The shared `.mjs` module is the seam; the dispatcher tasks (6–7) run in parallel with the doctor chain (2→5) after Task 1.
- **Dispatcher staleness = content compare.** Doctor flags the installed dispatcher stale when its bytes differ from the active package's `bin/pi-flow-dispatch.mjs`; `--fix` re-copies. (Chosen over a version stamp for zero maintenance; a stamp can be layered on later without changing the surface model.)
- **Dispatcher bootstrap candidate list is the only inline knowledge.** The installed launcher probes `~/.pi/agent/npm/node_modules/@aphotic/pi-flow-core/extensions/lib/effective-package.mjs` then the aggregate-nested `.../@aphotic/pi-flow/node_modules/@aphotic/pi-flow-core/extensions/lib/effective-package.mjs`. All semantic resolution (trust, override, identity, npm-spec) lives in the imported module — the candidate list is a launcher concern, not duplicated resolution logic.
- **Local/git override resolution is best-effort.** The dispatcher resolves a local/path override only when the declared root resolves to a usable core; otherwise it falls back to the user target. Documented as a limitation.

## Risk Assessment

- **Bare-node importability of the shared module.** The `.mjs` must run under plain `node` (no strip-types) with builtin-only imports. Risk: an accidental `.ts` import or third-party dependency breaks the dispatcher silently. Mitigation: Task 1's first acceptance criterion imports the module under bare node; the dispatcher tests (Task 6) exercise the real import path.
- **`.ts` importing a runtime `.mjs` under strip-types.** Re-pointing `package-resolution.ts`/`doctor.ts` at the `.mjs` relies on Node ESM allowing a `.ts` (strip-types) file to import a `.mjs`. Risk: resolution or typecheck failure. Mitigation: Task 2 runs `tsc --noEmit` plus the existing suites as acceptance; if strip-types rejects the import, fall back to keeping typed `.d.ts`-style declarations alongside the `.mjs` (the function shapes are stable).
- **Dispatcher chicken-and-egg bootstrap.** The installed launcher must locate the shared module before it can resolve anything. Risk: a hardcoded candidate list drifts from real install layouts, or no user install exists. Mitigation: the candidate list is the single documented inline concession; Task 6 covers the no-module fallback (degrade to bootstrap user core, else actionable stderr, never crash).
- **Serial edits to `doctor.ts`.** Tasks 2→3→4→5→8→9 all modify `doctor.ts`; the dependency chain serializes them to avoid write conflicts. Risk: a broken intermediate state. Mitigation: each task's acceptance runs the doctor suite, so regressions surface at the task boundary.
- **Changing the never-overwrite shim semantics.** Switching the shim from a symlink to a real file copy must migrate the legacy owned symlink without clobbering a user's foreign file or a divergent symlink. Mitigation: Task 7 treats a regular file matching the dispatcher signature as "ours" (refresh), migrates a symlink that resolves into a managed pi-flow core `bin/pi-flow.mjs` to the dispatcher copy, and preserves all other foreign files, directories, and non-pi-flow symlinks via the existing conflict/preserved-other outcomes (covered by tests).
- **Fixing `parseDeclaredPackages` flips an existing expectation.** The bug fix reclassifies a bare `"npm:..."` string from `local` to `npm`. Mitigation: Task 2 explicitly updates the one affected `doctor.test.ts` assertion; a bare path string stays `local`.
