### Issues

#### Critical (Must Fix)

_None._

#### Important (Should Fix)

- **Task 8: `--fix` effective-agent repair lacks direct acceptance coverage**
  - **What:** Task 8 Step 3 says `runDoctorFix` must repair only the active/effective-scope resolution surfaces, including the effective scope's agent symlinks, but the acceptance criteria only verify stale dispatcher refresh, inactive install preservation, foreign shim preservation, and settings immutability.
  - **Why it matters:** An executor could implement dispatcher refresh correctly while regressing the spec's scope-aware agent-symlink repair behavior, especially for trusted project overrides where project agents and user agents must be treated separately.
  - **Recommendation:** Add an acceptance criterion and `Verify:` recipe for a trusted-project override where `--fix` repairs project agent symlinks without rewriting unrelated user-scope agents, plus the inverse user-effective case.

- **Task 3: First verify recipe can mask a failing test run**
  - **What:** The first Task 3 `Verify:` command pipes the `node --test` output into `grep -q "inactive-overridden"` and then states that the suite exits 0. Without `set -o pipefail` or an explicit two-command check, the shell exit status is the `grep`, not the test command.
  - **Why it matters:** A failing doctor test run that prints the searched text could satisfy the recipe, giving a false pass for a core classification task.
  - **Recommendation:** Change the recipe to run the test command directly for exit 0 and use a separate grep/assertion only on a captured artifact, or rely on a named subtest assertion and require the full `node --test` command to exit 0.

#### Minor (Nice to Have)

- **Task 9: Handler-level strict notification behavior is under-verified**
  - **What:** Task 9 Step 2 changes notify level selection for strict divergence, but acceptance only checks parsing/help and the full suite.
  - **Why it matters:** The diagnosis-level strict behavior is tested in Task 3, so this is low risk, but the final handler wiring could still omit the `error` notification level for strict divergence.
  - **Recommendation:** Add a small handler or registration test asserting `strict && strictDivergence` uses the error notify level.
