### Issues

#### Critical (Must Fix)

#### Important (Should Fix)

- **Task 2: Project config path uses cwd instead of the specified project root**
  - **What:** The resolver is specified as `path.join(cwd, ".pi", "ideas.json")` with `cwd` defaulting to `process.cwd()`, while the spec’s chosen approach names `<project-root>/.pi/ideas.json`. The plan’s Risk Assessment acknowledges that launching Pi from a subdirectory would miss the true project-level config.
  - **Why it matters:** This is a visible deviation from the chosen file-based project/global approach: project configuration may silently not apply in non-root launch contexts.
  - **Recommendation:** Either resolve the actual project root before reading `.pi/ideas.json`, or explicitly make “Pi launch cwd is the project root” a documented contract and include tests/docs that reflect that limitation.

- **Task 6: Standalone loader smoke test does not isolate project config via `process.cwd()`**
  - **What:** The test isolates `HOME`/`USERPROFILE` and passes a sandbox `cwd` to `DefaultResourceLoader`, but `registerIdea(pi)` in the standalone entry resolves project config from `process.cwd()` unless options are supplied. Unlike Task 7’s core loader test, Task 6 does not `process.chdir()` into the sandbox.
  - **Why it matters:** A repository or developer `.pi/ideas.json` under the test process cwd could override the default `ideas` command and make the smoke test flaky or fail its `extension.commands.has("ideas")` assertion.
  - **Recommendation:** Mirror Task 7’s hermetic pattern: save cwd/env, `process.chdir()` into the sandbox during the loader test, then restore in `finally`.
