## Context

`@aphotic/pi-flow-ux` has both a footer status renderer and a border-status editor renderer. The desired default is the border-status editor, while still allowing users to choose the footer renderer or disable status UI entirely. Only one status placement should be active at any point in time.

The existing `working.json` convention is a three-tier configuration model: hardcoded code defaults, packaged defaults shipped with `@aphotic/pi-flow-ux`, and a user-global override file under `~/.pi/agent/`. User override files may be partial, with missing fields filled from lower tiers. Missing user config falls back to packaged defaults; malformed user config falls back until corrected; missing packaged defaults fall back to code defaults; malformed packaged defaults fail loudly. Mutating commands persist only to the user-global file and never modify packaged defaults. This convention is user-global only today; it does not include project-specific config.

## Goal

Create a single owning status extension that coordinates status UI placement for both direct `@aphotic/pi-flow-ux` installs and aggregate `@aphotic/pi-flow` installs. It should install exactly one of: border-status editor, footer renderer, or no status UI. The default placement should be `border`, persisted user preference should live in `~/.pi/agent/status.json`, and users should be able to inspect or change placement in-session through `/status`.

## Scope

- Add a unified status extension, likely `packages/pi-flow-ux/extensions/status/index.ts` or `packages/pi-flow-ux/extensions/status.ts`.
- Move or wrap the existing border-status and footer installation logic behind the coordinator so those renderers are implementation choices, not independently loaded extensions.
- Add status configuration with the same conventions as `working.json`:
  - hardcoded code default: `placement: "border"`;
  - packaged default: `packages/pi-flow-ux/status.json`, shipped with the package;
  - user-global override: `~/.pi/agent/status.json`;
  - partial user overrides merge over packaged/code defaults;
  - missing user config falls back to packaged defaults;
  - malformed user config falls back until corrected;
  - missing packaged defaults fall back to code defaults;
  - malformed packaged defaults fail loudly;
  - command mutations persist only to `~/.pi/agent/status.json`, preferably with the same atomic-write behavior as `working.json`.
- Use a simple status config schema such as `{ "placement": "border" | "footer" | "off" }`.
- Register `/status`:
  - `/status` reports the current placement and accepted values;
  - `/status border`, `/status footer`, and `/status off` switch placement immediately in the current session and persist the user override.
- Ensure mutual exclusion: when `border` is active, the footer renderer is not installed; when `footer` is active, the border editor is not installed; when `off`, neither is installed.
- Remove independent manifest loading of `extensions/footer.ts` and `extensions/border-status.ts`; do not add compatibility shims. Existing renderer code may remain only as internal implementation modules if useful.
- Update both package manifests so the unified status extension is loaded by default:
  - direct package install: `packages/pi-flow-ux/package.json`;
  - aggregate install: `packages/pi-flow/package.json`.
- Update package `files`/packlist coverage so `status.json` ships with direct and aggregate package installs.
- Preserve the existing working indicator/message extension behavior and keep it independent from status placement.
- Update README/docs to describe `/status`, `~/.pi/agent/status.json`, the default `border` placement, no project-specific config layer, and direct-vs-aggregate install behavior.

## Acceptance Sketch

- Loading `@aphotic/pi-flow-ux` directly defaults to the border-status editor and does not also install the footer renderer.
- Loading aggregate `@aphotic/pi-flow` defaults to the same unified status behavior.
- `/status` with no args reports the current placement and valid options.
- `/status footer`, `/status border`, and `/status off` switch immediately in-session and persist to `~/.pi/agent/status.json`.
- The selected placement persists across Pi reloads/sessions.
- `border`, `footer`, and `off` are mutually exclusive in tests and runtime behavior.
- Missing/malformed user config and missing/malformed packaged config follow the same semantics as `working.json`.
- Existing footer and border-status rendering behavior is preserved when selected.
- Existing working indicator/message behavior is unchanged.
- Tests cover default placement, switching, persistence, config layering/failure semantics, direct `pi-flow-ux` manifest wiring, aggregate `pi-flow` manifest wiring, package files/packlist behavior, and absence of independent footer/border-status manifest entries.
