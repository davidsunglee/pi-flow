## Context
The `fastlane` workflow skill currently references `execute-plan` internals, including `skills/execute-plan/tdd-block.md`, `pi-flow helper execute-plan/parse-coder-report`, mirrored status-routing language, and mirrored idea-closure steps. Both skills are large, and cross-skill references to large workflow steps make maintenance harder.

## Goal
Decouple `fastlane` from `execute-plan` by moving reusable, stable primitives into `_shared` and replacing direct large-skill references with small shared contracts or procedures.

## Scope
- Move the reusable coder TDD block from `skills/execute-plan/tdd-block.md` to a shared location such as `skills/_shared/coder-tdd-block.md`.
- Move or wrap `parse-coder-report.py` as a shared helper, e.g. `pi-flow helper _shared/parse-coder-report`, while optionally keeping a temporary compatibility shim under `execute-plan`.
- Add a shared coder report/status contract describing valid statuses and parser expectations.
- Replace Fastlane references like “mirror execute-plan Step 9” with references to the shared contract plus local Fastlane routing.
- Extract linked idea closure into a small shared procedure parameterized by completion note and source lookup behavior.
- Update `fastlane`, `execute-plan`, related helpers, docs, and tests.
- Avoid moving truly plan-specific assets such as plan parsing, verifier helpers, and execute-task prompt assembly unless they prove reusable.

## Acceptance Sketch
- `fastlane/SKILL.md` no longer references `skills/execute-plan/`, `pi-flow helper execute-plan/parse-coder-report`, or `execute-plan` step numbers for mirrored behavior.
- Both `fastlane` and `execute-plan` use shared primitives for the coder TDD block and coder report parsing.
- Shared docs are small and contract-focused, not another large workflow skill.
- Existing parser/helper tests pass, with new or updated tests covering shared helper paths and Fastlane decoupling guardrails.

## Open Questions
- Should the old `execute-plan/parse-coder-report` helper remain as a compatibility shim, and for how long?
- What exact shared filenames should be used for the TDD block, coder report contract, and linked idea closure procedure?
- Should guardrail tests forbid all `execute-plan` references from `fastlane`, or only references to internal files/helpers/step numbers?
