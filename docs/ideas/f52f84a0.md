## Context

`@aphotic/pi-flow-ux` now coordinates status placement through a unified status extension. When `status.placement` is `border`, session metadata is drawn into the editor border, but Pi's built-in/default footer can still show redundant model/context/session information below the editor.

## Goal

When border status is active, blank out the default footer so the border is the only visible session-status surface. Footer placement should continue to show the custom footer, and `off` should restore Pi's normal built-in/default footer behavior.

## Scope

- Add a tiny blank-footer renderer/handle that calls `ctx.ui.setFooter(() => ({ render: () => [], invalidate() {} }))` and restores the default footer with `ctx.ui.setFooter(undefined)` on dispose.
- Use the blank-footer renderer only for `status.placement === "border"`.
- Compose the border editor handle and blank-footer handle so switching away from `border` disposes both resources cleanly.
- Keep `status.placement === "footer"` installing the custom footer renderer as it does today.
- Keep `status.placement === "off"` installing no status renderer and restoring Pi's default footer.
- Preserve existing working indicator/message behavior.
- Update README/docs to explain that border placement suppresses the built-in footer to avoid duplicated metadata.

## Acceptance Sketch

- Starting Pi with default/border placement installs the border editor and suppresses the default footer.
- The blank footer renders no lines.
- Switching from `border` to `footer` disposes the blank footer and shows the custom footer renderer.
- Switching from `border` to `off` disposes the blank footer, removes the border editor, and restores the built-in/default footer.
- Switching back to `border` suppresses the footer again.
- Session shutdown restores the built-in/default footer.
- Tests cover the lifecycle and switching behavior.
