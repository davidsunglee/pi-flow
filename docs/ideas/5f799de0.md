## Context
The execute-plan skill currently prompts the user between waves whenever integration tests fail after a wave completes. That is appropriate when tests are expected to pass between waves, but some plans intentionally leave integration failures until future waves complete related work. Agents sometimes recognize and explain that a failure is expected because later plan work will address it.

## Goal
Update execute-plan so expected interim integration test failures do not block execution with a user prompt when specific future plan work is expected to fix them.

## Scope
- Modify the between-wave integration-test failure handling in the execute-plan skill.
- Add a conservative classification step: skip the prompt only when the executor can point to concrete future wave/task work expected to resolve the failing integration test(s).
- Notify the user instead of prompting when failures are expected, including the failing test(s), why they are expected, and which future wave/task should address them.
- Preserve the existing prompt/menu behavior for unexpected, ambiguous, mixed, or unlinked failures.
- Preserve existing exact menu text where tests or downstream workflows may depend on it.

## Acceptance Sketch
- Expected integration failures between waves produce a notification and execution continues to the next wave.
- Unexpected or ambiguous integration failures still display the existing choices exactly as today.
- The skill text discourages using future work as a blanket excuse to ignore regressions.
- Relevant pi-flow-core skill guardrail tests pass.

## Open Questions
- Should mixed failures allow continuing for expected failures while still prompting for unexpected ones, or should any unexpected failure trigger the existing prompt for the whole integration-test result?
