## Context
Anthropic Claude Fable 5 is available in the current Pi environment as the exact active provider/model identifier `anthropic/claude-fable-5`. pi-flow currently models local/provider-preferred dispatch with `modelTiers.capable`, `modelTiers.standard`, and `modelTiers.cheap`, plus analogous `crossProviderModelTiers` entries, but it has no abstract tier above `capable`. Workflows that should use frontier-class models therefore cannot express that intent without hardcoding model names in skill logic.

The existing `cheap` tier name should also be replaced. The desired canonical terminology is `efficient`, and this project can tolerate a clean hard cutover because it is not supporting external users or long-lived third-party configurations.

## Goal
Introduce a new abstract logical tier named `frontier` and rename the existing `cheap` tier to `efficient` across pi-flow. Configure provider-preferred frontier dispatch to use `anthropic/claude-fable-5`, configure cross-provider frontier dispatch to use `openai-codex/gpt-5.5`, and route `spec-designer` and `planner` through `modelTiers.frontier` so future model churn remains isolated to flow configuration rather than skill code.

## Scope
- Add `frontier` to both `modelTiers` and `crossProviderModelTiers` configuration shape and dispatch documentation.
- Configure `modelTiers.frontier` with `anthropic/claude-fable-5`.
- Configure `crossProviderModelTiers.frontier` with `openai-codex/gpt-5.5` until a newer cross-provider frontier model is available.
- Update `define-spec` / `spec-designer` dispatch and `generate-plan` / `planner` dispatch to use `modelTiers.frontier` instead of `modelTiers.capable`.
- Rename `modelTiers.cheap` to `modelTiers.efficient` and `crossProviderModelTiers.cheap` to `crossProviderModelTiers.efficient` throughout pi-flow configuration, helpers, skill docs, prompts, tests, fixtures, and user-facing settings.
- Make the rename a clean hard cutover: do not keep `cheap` as a deprecated alias, fallback path, compatibility shim, or accepted tier spelling in pi-flow-owned code.
- Preserve the abstract tier names in skills and workflow logic; concrete model names belong in configuration, documentation examples, and resolution tests rather than skill dispatch sites.

## Acceptance Sketch
- `pi-flow helper _shared/resolve-model-dispatch --tier modelTiers.frontier --agent spec-designer` resolves successfully when `modelTiers.frontier` is configured as `anthropic/claude-fable-5`.
- `pi-flow helper _shared/resolve-model-dispatch --tier modelTiers.frontier --agent planner` resolves successfully under the same configuration.
- `define-spec` resolves `spec-designer` through `modelTiers.frontier`.
- `generate-plan` resolves the initial `planner` dispatch through `modelTiers.frontier`.
- `crossProviderModelTiers.frontier` exists and resolves through the existing dispatch helper when configured to `openai-codex/gpt-5.5` and an `openai-codex` subagent dispatch mapping is present.
- All pi-flow-owned tier references use `efficient` instead of `cheap`; there is no alias, fallback logic, or accepted `cheap` tier spelling remaining for model-tier resolution or workflow settings.
- Existing behaviors that previously selected the low-cost/fast tier now select `efficient` via the renamed tier path.
- Tests cover frontier tier resolution, spec-designer/planner frontier dispatch selection, cross-provider frontier resolution, the clean cheap-to-efficient cutover, and parser/fixture updates for execution-plan model recommendations if those recommendations include the renamed tier.
- Documentation and user-facing menus describe the canonical tiers as `frontier`, `capable`, `standard`, and `efficient`.
