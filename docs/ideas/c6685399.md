## Context

When choosing to refine an idea in the ideas package, the current prompt often does not generate enough clarifying questions to answer the idea's existing `## Open Questions` section.

The likely cause is prompt structure: it asks the model to "ask questions until you can satisfy the following structure," then includes `## Open Questions` as one of the required output sections. Because open questions are treated as an acceptable final section rather than work to resolve, the model can stop too early and preserve unresolved questions instead of driving the refinement conversation toward answers.

## Goal

Change the idea-refinement prompt so refinement explicitly prioritizes resolving existing open questions before rewriting the structured idea body.

The final `## Open Questions` section should contain only genuinely unresolved questions that remain after targeted clarification, not questions the refine flow failed to ask.

## Scope

- Audit the pi-ideas refinement prompt used when the user chooses to refine an existing idea.
- Reword the prompt so it distinguishes between:
  - questions to ask the user during refinement; and
  - the final `## Open Questions` section in the idea artifact.
- Instruct the model to inspect the existing `## Open Questions` section first and ask targeted clarifying questions whose answers would materially change the artifact.
- Keep the canonical idea body shape:
  - `## Context`
  - `## Goal`
  - `## Scope`
  - `## Acceptance Sketch`
  - `## Open Questions`
- Make the default refinement outcome reduce or eliminate open questions when the user can answer them.
- Preserve an `## Open Questions` section for genuinely unresolved items, deferred decisions, or questions the user cannot answer yet.
- Add prompt/behavior regression coverage if the ideas package has prompt tests.

## Acceptance Sketch

- Given an idea with existing open questions, the refine flow asks about those questions before rewriting the body.
- The prompt no longer implies that leaving open questions populated is sufficient refinement when answerable questions remain.
- The rewritten idea body still uses the canonical five section headers in order.
- The final `## Open Questions` section is empty/`None` when all material questions were answered.
- Tests or prompt snapshots fail if refinement guidance regresses to treating `## Open Questions` as a passive catch-all instead of an active refinement target.
