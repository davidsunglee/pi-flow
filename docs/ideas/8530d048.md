## Context
The monorepo currently includes an idea extension that should be separated from its current location into a clean package boundary. The target package name is `@aphotic/pi-ideas`, and it should be ready for external publication even though publishing itself is out of scope for this implementation.

The current plug-in has logical dependencies on `pi-flow-core`. For example, workflow actions in the work submenu insert prompts that reference commands registered by `pi-flow-core`. Those workflow-specific menu items should move out of the idea extension and into external configuration supplied by `pi-flow-core` or another consumer. This keeps the ideas package reusable while preserving the existing pi-flow workflow integration.

## Goal
Extract the idea extension into a standalone, publishable monorepo package named `@aphotic/pi-ideas` with a configurable work submenu. The package should have no required dependency on `pi-flow-core` workflow commands, while `pi-flow-core` should continue to provide its current workflow actions through configuration.

## Scope
- Create a dedicated workspace package named `@aphotic/pi-ideas` with publication-ready metadata, exports, dependency declarations, build configuration, and tests.
- Move the idea extension source, tests, and relevant package-level configuration into the new package.
- Remove required logical dependencies from the idea extension to `pi-flow-core` workflow commands.
- Add an external work-menu action configuration API.
- Support configured work-menu actions with:
  - a submenu item name, such as `spec`;
  - a prompt template inserted into the editor when selected;
  - an `<idea>` placeholder in the prompt template that is replaced with the selected idea id;
  - an optional keyboard shortcut, such as `ctrl+shift+r`, so the UI can display the hotkey in the quick reference bar.
- Hide the work submenu when no work-menu actions are configured.
- Update `pi-flow-core` to provide the existing workflow actions through the new external configuration mechanism.
- Add minimal README/docs for configuring work-menu actions, including the required fields, `<idea>` placeholder behavior, optional shortcut display, and no-actions submenu hiding behavior.
- Preserve current behavior for existing pi-flow workflows after configuration is wired through.
- Do not publish the package as part of this implementation.

## Acceptance Sketch
- The monorepo includes a standalone `@aphotic/pi-ideas` package in workspace configuration.
- The package is publishable/public-ready, but no publication is performed during implementation.
- The ideas package does not require `pi-flow-core` workflow commands or private implementation paths.
- The ideas package exposes a documented configuration mechanism for work-menu actions.
- The work submenu is hidden when no actions are configured.
- Configured actions render with their names, insert prompt templates with `<idea>` replaced by the selected idea id, and optionally display configured shortcuts.
- `pi-flow-core` supplies its existing workflow actions through external configuration, preserving current pi-flow behavior.
- Relevant tests, type checks, and builds pass after the extraction.
- README/docs explain how another workflow package could configure the ideas work submenu.
