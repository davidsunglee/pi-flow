## Context
`execute-plan` and related workflows dispatch the `test-runner` subagent through the shared four-input contract in `packages/pi-flow-core/skills/_shared/test-runner-dispatch.md`. The current flow configuration still resolves `crossProviderModelTiers.cheap` for `agent=test-runner` to Codex in this environment:

```json
{"model":"openai-codex/gpt-5.4-mini","cli":"codex","provider":"openai-codex","tier":"crossProviderModelTiers.cheap","executionPolicy":"unrestricted"}
```

The original failure occurred while executing `docs/plans/2026-06-03-f5ddba6d.md`: Codex-backed `test-runner` ran the supplied test command successfully but wrote a shortened artifact such as:

```text
PHASE: baseline
FAILING_IDENTIFIERS:
NON_RECONCILABLE_FAILURES:
```

That artifact omitted required parser headers and markers including `COMMAND:`, `WORKING_DIRECTORY:`, `EXIT_CODE:`, `TIMESTAMP:`, `FAILING_IDENTIFIERS_COUNT:`, `END_FAILING_IDENTIFIERS`, `NON_RECONCILABLE_COUNT:`, `END_NON_RECONCILABLE_FAILURES`, and `--- RAW RUN OUTPUT BELOW ---`. The orchestrator-side parser correctly rejected it with:

```json
{"failure":"header_missing","detail":"expected 'COMMAND', got 'FAILING_IDENTIFIERS:'"}
```

Recent source changes in `../pi-mux-subagents` address one likely harness-level cause: Codex has no system-prompt channel, so the new identity-delivery seam keeps agent identity/body text in the Codex task body even when an agent declares `system-prompt: append|replace`. Targeted source tests now cover this, including Codex delivery of a test-runner-shaped artifact contract into both pane and headless prompts.

However, a live smoke dispatch in this environment still reproduced the malformed artifact shape:

```text
PHASE: idea-9dfc2062-smoke
FAILING_IDENTIFIERS:
NON_RECONCILABLE_FAILURES:
```

and `parse-test-runner-artifact.py` again failed with `header_missing`. That smoke is not definitive proof that the latest source still fails, because the active runtime is stale: `which pi-flow` resolves to `/Users/david/.pi/agent/bin/pi-flow`, whose realpath is `/Users/david/.pi/agent/npm/node_modules/@aphotic/pi-flow-core/bin/pi-flow.mjs`; the installed pi-flow-core version observed there is `0.6.0`, while the repo source is `0.8.0`. The installed `@aphotic/pi-mux-subagents` source also lacks the new identity-delivery file. `IDEA-b79bac29` tracks the prerequisite environment-maintenance issue of keeping shims/symlinks aligned to the intended package version.

The current repo-local `test-runner` agent and prompt already state the full artifact format strictly, and parser strictness remains appropriate. The unresolved question is whether Codex-backed `test-runner` succeeds after the runtime is aligned to current source; if not, additional hardening or dispatch policy is still needed.

## Goal
Make `test-runner` artifact production reliable when `test-runner` resolves to Codex, or intentionally route `test-runner` away from Codex with documented, tested dispatch policy.

The fix must preserve the workflow boundary: integration test commands are run by `test-runner` subagents, not by the orchestrator directly, and artifacts are trusted only after validation by `pi-flow helper _shared/parse-test-runner-artifact`.

## Scope
1. **Retest after runtime alignment**
   - First ensure the active `pi-flow` shim/symlink and `@aphotic/pi-mux-subagents` runtime point to the intended current package versions/source.
   - Re-run a Codex-backed `test-runner` smoke with `crossProviderModelTiers.cheap` and validate the artifact with `parse-test-runner-artifact.py`.

2. **Prompt/harness verification**
   - Keep or extend the existing `pi-mux-subagents` identity-delivery coverage proving Codex receives the `test-runner` artifact contract despite `system-prompt: append`.
   - Confirm both pane and headless Codex dispatch paths deliver the agent body and per-call prompt without duplication or omission.

3. **Artifact-generation hardening if Codex still writes malformed artifacts**
   - Prefer a deterministic helper/wrapper callable by the `test-runner` subagent that runs the supplied command, captures combined output/exit code, and writes a parser-valid artifact from structured inputs.
   - Alternatively further localize and simplify the artifact skeleton in `test-runner.md` / `_shared/test-runner-prompt.md` if evidence shows prompt locality is enough.
   - Preserve the rule that the subagent runs the supplied test command and writes the artifact; do not move test execution or artifact synthesis into the orchestrator.

4. **Dispatch policy fallback if Codex remains unreliable**
   - If Codex cannot reliably satisfy this protocol, change dispatch configuration/resolution so `agent=test-runner` does not select `cli: codex` for the cheap cross-provider tier.
   - Document and test the intentional fallback, e.g. selecting a Claude-backed cheap model for protocol-heavy `test-runner` runs.

5. **Malformed-artifact surfacing**
   - Ensure execute-plan/fastlane callers surface parser failures clearly as `artifact_malformed` (with parser JSON/detail and transcript/artifact paths where available) instead of repeatedly redispatching as though the subagent succeeded.

Out of scope:

- Weakening `parse-test-runner-artifact` to accept partial artifacts.
- Having the orchestrator run the configured test command itself.
- Synthesizing test-runner artifacts in the orchestrator from local command output.

## Acceptance Sketch
- Active runtime alignment is verified before judging Codex behavior: `pi-flow` shim realpath/version and loaded `@aphotic/pi-mux-subagents` source/version match the intended current package/source.
- A Codex-backed `test-runner` smoke either:
  - writes a parser-valid full artifact containing, in order when a phase is present:

```text
PHASE: <phase>
COMMAND: <command>
WORKING_DIRECTORY: <working directory>
EXIT_CODE: <integer>
TIMESTAMP: <ISO-8601 UTC timestamp>
FAILING_IDENTIFIERS_COUNT: <N>
FAILING_IDENTIFIERS:
...
END_FAILING_IDENTIFIERS
NON_RECONCILABLE_COUNT: <M>
NON_RECONCILABLE_FAILURES:
...
END_NON_RECONCILABLE_FAILURES

--- RAW RUN OUTPUT BELOW ---
<full raw output>
```

  - or `test-runner` dispatch intentionally avoids Codex, with tests/docs proving the policy.
- This parser invocation succeeds for the smoke artifact:

```bash
pi-flow helper _shared/parse-test-runner-artifact \
  --artifact <artifact-path> \
  --final-message <final-message-path-or-stdin> \
  --expected-path <artifact-path> \
  --freshness-baseline <mtime-before-dispatch>
```

- `execute-plan` Step 7 baseline capture can proceed without protocol failure under the chosen policy.
- Regression coverage exists for:
  - Codex prompt/identity delivery of the `test-runner` artifact contract.
  - Parser rejection of shortened artifacts.
  - Caller surfacing of malformed artifacts without treating subagent exit success as protocol success.
  - Any intentional non-Codex dispatch policy for `agent=test-runner`.

## Open Questions
- After `IDEA-b79bac29` aligns shims/symlinks to current source, does Codex still write shortened artifacts, or was the remaining live failure entirely due to stale runtime?
- If latest-source Codex still fails, is the root cause prompt adherence, Codex write/tool behavior, final-message handling, or the complexity of manually formatting the artifact?
- Should `test-runner` artifact writing move to a deterministic helper callable by subagents?
- Should protocol-heavy agents such as `test-runner` have provider exclusions/preferences separate from generic tier resolution?
- If a malformed artifact is encountered, should callers stop immediately with a clear protocol error, retry once with a stronger prompt, or fall back to a safer provider?
