## Context
The current Working Indicator/message can get visually lost because extensions such as Subagents and Todo occupy the space directly above the prompt editor. The status extension already uses the editor border for persistent session metadata like model, thinking level, cwd, branch, and context usage.

## Goal
Create a cleaner, more discoverable home for working state by adding a fixed-width activity indicator slot immediately to the left of the model name in the editor bottom border.

## Scope
- Add a reserved indicator slot before the model name in the border status line.
- When active, render a single-cell animated indicator such as a pulse or spinner, followed by one space.
- When idle, render a horizontal border segment in the same slot so the border remains visually continuous instead of leaving a gap.
- Keep the model name and thinking level layout stable with no horizontal jitter.
- Use modest animation timing and single-width glyphs only.
- Keep full working messages out of the border for now; this idea covers the compact indicator placement only.

## Acceptance Sketch
- Active example: `╰─ ⠋ claude-sonnet-4-5 xhigh ───── 42k/200k 21.0% ─╯`
- Idle example: `╰─── claude-sonnet-4-5 xhigh ───── 42k/200k 21.0% ─╯`
- The slot has constant visible width across idle, pulse, and spinner frames.
- Animation runs only during active turns/thinking/tool-use states.
- Frames do not trigger layout jitter or expensive recomputation.
- Narrow terminal behavior preserves the existing border priority/drop rules.

## Open Questions
- Should the slot use spinner or pulse by default?
- Should the active indicator color reflect working state (`active`, `thinking`, `toolUse`) or use one consistent accent color?
- Should this replace the current built-in working indicator entirely or coexist with a configurable full working message elsewhere?
