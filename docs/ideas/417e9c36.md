## Context
The status extension currently supports `border`, `footer`, and `off` configuration modes. The current working indicator and working message can get visually lost because extensions such as Subagents and Todo occupy the space directly above the prompt editor. The status extension already uses the editor border for persistent session metadata like model, thinking level, cwd, branch, and context usage, making the border a better home for compact working state when border status is enabled.

## Goal
Make working state placement follow the status extension mode: in `border` mode, embed a compact working indicator into the editor bottom border immediately to the left of the model name; in `footer` mode, keep the full working indicator and working message in the existing footer location; in `off` mode, preserve the current behavior with no customization of the working indicator or working message.

## Scope
- For status `border` mode, add a reserved fixed-width activity indicator slot before the model name in the editor bottom border.
- When active in `border` mode, render the existing working indicator animation/effects in that slot, including the current gleam and rainbow behavior.
- When idle in `border` mode, render a horizontal border segment in the same slot so the border remains visually continuous instead of leaving a gap.
- Keep the model name and thinking level layout stable with no horizontal jitter across idle, gleam, rainbow, pulse, and spinner frames.
- Use only single-width glyphs in the border slot and keep animation timing modest.
- For status `footer` mode, keep the full working indicator plus working message in the existing location with all current effects intact.
- For status `off` mode, keep the current behavior: no status-extension customization for the working indicator or working message.
- Keep full working messages out of the border; the border mode covers compact indicator placement only.

## Acceptance Sketch
- Border active example: `╰─ ⠋ claude-sonnet-4-5 xhigh ───── 42k/200k 21.0% ─╯`
- Border idle example: `╰─── claude-sonnet-4-5 xhigh ───── 42k/200k 21.0% ─╯`
- In `border` mode, active turns/thinking/tool-use states animate the fixed slot to the left of the model name.
- In `border` mode, the indicator preserves the current working indicator's gleam and rainbow effects.
- In `border` mode, the slot has constant visible width across idle, pulse, spinner, gleam, and rainbow frames.
- In `border` mode, frames do not trigger layout jitter or expensive recomputation.
- In `border` mode, narrow terminal behavior preserves the existing border priority/drop rules.
- In `footer` mode, the full working indicator and working message continue to appear in their current location with current effects.
- In `off` mode, working indicator/message behavior remains unchanged from today.
