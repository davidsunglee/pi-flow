## Context

This idea is limited to pi-flow prompt-language changes. Related pi-mux-subagents launcher/addendum behavior is tracked separately in `IDEA-f6eac473` in `/Users/david/Code/pi-mux-subagents`.

Codex-backed pi-flow subagents can have the `subagent_done` completion tool available and still fail to close under `auto-exit: true` when prompts instruct them to emit a final answer first. Diagnostics showed that Codex can call `subagent_done` successfully when directly instructed, but prompt variants such as "your FINAL assistant message should summarize what you accomplished, then call `subagent_done`" lead Codex to emit a terminal final answer and stop before the tool call.

Real session logs and minimal reproductions showed the same pattern: final-answer-first wording produces `assistant/final_answer` with no MCP call, while tool-first wording makes Codex call `subagent_done`.

pi-flow should therefore describe completion as a tool-first protocol while preserving existing visible marker lines and byte-equality parsing contracts used by parent orchestrators.

## Goal

Update pi-flow workflow prompts so completion is described as a tool-first protocol: prepare the exact completion message, emit the visible completion/marker line immediately before the tool call, then call `subagent_done` as the completion signal. A visible final answer or marker line alone must not be described as completion.

Centralize the completion-protocol wording in a shared prompt snippet or equivalent shared source so runtime prompts do not drift back toward final-answer-first instructions.

## Scope

- Audit pi-flow runtime-dispatched subagent prompts and shared prompt sources for wording that says or implies "final assistant message ... then call `subagent_done`."
- Replace that wording with backend-neutral, tool-first completion language such as:

  ```text
  Completion protocol:
  When the task is complete, prepare the exact completion message to return to the parent.
  Emit that message visibly as the final visible line immediately before the tool call.
  Then call `subagent_done(message="<exact completion message>")` as the completion signal.
  The visible completion line alone is not completion.
  Do not end the session by sending a final answer alone.
  Do not emit further output after `subagent_done`.
  If this environment's `subagent_done` tool has no `message` argument, call `subagent_done()` immediately after the visible completion message.
  ```

- For artifact/marker workflows, use an explicit `DONE_MESSAGE` contract:

  ```text
  Set DONE_MESSAGE to `REVIEW_ARTIFACT: <absolute path>`.
  Your visible completion line must be exactly DONE_MESSAGE.
  Then call `subagent_done(message=DONE_MESSAGE)`.
  The tool call is the completion signal; the visible line alone is not completion.
  ```

- Keep visible marker lines mandatory for compatibility and fallback behavior across backends.
- Preserve existing artifact marker parsing and byte-equality requirements for parent orchestrators.
- Centralize the completion-protocol wording in one shared prompt snippet or equivalent shared source, then reference/interpolate it from affected runtime prompts.
- Add guardrail coverage for runtime-dispatched subagent prompts and the shared completion snippet. Do not require broad tests over all skill documentation unless that documentation directly generates runtime prompts.
- Do not change pi-mux-subagents command construction or Codex-specific addenda here; that belongs to `IDEA-f6eac473` in the pi-mux-subagents project.

## Acceptance Sketch

- pi-flow runtime prompt sources no longer contain final-answer-first completion wording for `subagent_done`.
- A shared completion-protocol snippet or equivalent shared source defines the tool-first wording used by affected prompts.
- Marker-based prompts instruct agents to emit the exact required visible marker line immediately before calling `subagent_done(message=DONE_MESSAGE)` and state that the tool call is the completion signal.
- Existing pi and Claude workflows still complete and return markers as before.
- Codex-backed pi-flow review/test/spec/plan subagents no longer stop after a terminal final answer alone when the completion tool is available.
- A regression/guardrail test fails if runtime-dispatched prompt text or the shared snippet reintroduces "FINAL assistant message ... then call `subagent_done`" or equivalent final-answer-first wording.
