## Context
Claude-backed `test-runner` subagents are launched through pi-mux-subagents with the default guarded execution policy, which maps to Claude Code `--permission-mode auto` plus `CLAUDE_CODE_SANDBOXED=1`. This keeps Claude's permission classifier active, so even "auto" runs can prompt for actions such as `/tmp` access, bash execution, and artifact writes. The current `test-runner` instructions also recommend writing the test command to a temporary script while the dispatched prompt says not to modify any other file and to perform exactly one write to the artifact path, creating tension around temp-file use.

## Goal
Reduce or eliminate avoidable permission gates for trusted Claude-backed `test-runner` runs while preserving safety and the artifact contract.

## Scope
- Review whether `test-runner` should run with `execution-policy: unrestricted` by default, or whether callers should opt in per dispatch.
- Remove or revise the temp-script recommendation if it conflicts with the single-artifact-write rule.
- Consider a deterministic helper/wrapper for running the command and writing the artifact so the model does less permission-sensitive file/tool work.
- Document the distinction between Claude `auto` permission mode and unrestricted/bypass mode for future debugging.

## Acceptance Sketch
- Trusted Claude `test-runner` dispatches no longer prompt repeatedly for routine bash, `/tmp`, or artifact-write actions.
- The artifact parser still accepts generated artifacts reliably.
- The `test-runner` prompt and agent definition no longer conflict about temporary files versus exactly one artifact write.
- Docs explain when to use guarded vs unrestricted execution policy for Claude-backed subagents.

## Open Questions
- Should unrestricted be the default for all `test-runner` runs, or only for explicitly trusted integration gates?
- Is avoiding temp files sufficient, or is a dedicated helper needed to make test-runner execution deterministic?
- Are there project/workspace safety constraints that should keep some Claude test-runner invocations guarded?
