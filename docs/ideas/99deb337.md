## Context

The `test-runner` agent and the dispatched `test-runner` prompt currently give conflicting instructions about file writes. The agent definition recommends writing `## Test Command` verbatim to a temporary script file and executing it with `bash <script>` to avoid shell quoting corruption. The dispatched prompt, however, tells the subagent to modify no file except the artifact path and to perform exactly one write to `## Artifact Output Path`.

This creates ambiguity for any backend running `test-runner`: following the temporary-script recommendation violates the single-artifact-write/no-other-file contract, while avoiding temp files may make exact command preservation harder for commands containing quotes, heredocs, shell metacharacters, or multi-line scripts.

## Goal

Make the `test-runner` execution instructions internally consistent while preserving both requirements that matter: the test command reaches `bash` byte-for-byte as supplied, and the only durable file written by the subagent is the structured artifact at the requested artifact path.

## Scope

- Revise `packages/pi-flow-core/agents/test-runner.md` and/or `packages/pi-flow-core/skills/_shared/test-runner-prompt.md` so they no longer conflict about temporary files versus exactly one artifact write.
- Prefer a no-temp-file command execution mechanism when it can preserve the supplied command bytes reliably, such as feeding the command to `bash` via stdin/heredoc from the tool invocation.
- Clarify whether ephemeral shell constructs that do not create filesystem artifacts are allowed.
- Keep the artifact format, parser contract, handoff marker, and caller-side reconciliation behavior unchanged.
- Add or update regression coverage for the prompt/agent contract so future edits do not reintroduce contradictory file-write instructions.

## Acceptance Sketch

- The `test-runner` prompt and agent definition agree on the file-write contract: exactly one durable write to `## Artifact Output Path`, with no separate temp-script write requirement or recommendation.
- The instructions still explain how to run arbitrary supplied shell commands without quote corruption or command rewriting.
- The artifact parser continues to accept valid generated artifacts without changes to the artifact format.
- Tests or guardrails cover the absence of contradictory temp-file guidance alongside the single-artifact-write rule.

## Open Questions

- What exact no-temp-file invocation pattern should the prompt recommend for preserving command bytes through `bash`?
- Should the contract explicitly allow shell-level stdin/heredoc use while forbidding filesystem temp files?
- Is any backend-specific wording needed, or can the prompt stay backend-neutral?
