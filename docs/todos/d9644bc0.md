## Goal

Refactor the artifact-driven workflow terminology and identifiers from `TODO-<id>` to `IDEA-<id>` after the initial `pi-flow` extraction.

## Motivation

`todo` / `TODO` collides with common LLM planning/checklist tools and plugins. The workflow's durable user-intent artifacts should use Flow-specific idea terminology instead.

## Scope

- Rename the user-facing and LLM-facing file-backed todo tool surface to idea terminology.
- Migrate identifier parsing and provenance from `TODO-<8-hex>` to `IDEA-<8-hex>`.
- Audit and update workflow skills, prompts, helper scripts, parser tests, README docs, and examples that mention or parse `TODO-<id>`.
- Decide and implement backward compatibility for existing `TODO-<id>` artifacts and provenance lines.
- Provide migration guidance or tooling for existing `docs/todos/*.md` data if storage paths or metadata names change.

## Acceptance criteria

- Workflow entry points accept `IDEA-<id>` as the canonical durable artifact identifier.
- Specs/plans/briefs/reviews use `IDEA-<id>` provenance in newly generated artifacts.
- Existing `TODO-<id>` artifacts remain usable through an explicit compatibility path or documented migration.
- Tests cover canonical IDEA parsing and legacy TODO compatibility/failure behavior.
- Documentation explains the terminology change and how it avoids clashes with generic todo/checklist tools.

## Notes

Keep this separate from the initial `pi-flow` package extraction. The initial extraction may expose `/flow:idea` and an `idea` tool while retaining legacy `TODO-<id>` artifact compatibility.
